1.1 Problems in Procedure-Oriented Programming

Procedure-oriented programming (POP) relies on procedures or functions to perform tasks, but it has limitations that make it less suitable for complex, large-scale software development.

🔓 Lack of Data Security
Data is typically global and accessible to all functions, leading to unintended modifications. Example: A global variable in C can be altered by any function, risking data corruption.
📈 Poor Scalability
As programs grow, managing numerous functions and shared data becomes complex. Example: A large C program with many functions is hard to maintain.
♻️ Limited Reusability
Functions are often specific to a program, making reuse in other projects difficult. Example: A sorting function tailored for one data structure may not work for others.
🌍 Difficulty in Modeling Real-World Problems
POP focuses on procedures rather than entities, making it hard to represent real-world objects. Example: Modeling a "car" with attributes and behaviors is unnatural in POP.

Key Limitations of POP

  • Maintenance Challenges: Changes in one function can affect others due to shared data, complicating debugging. Example: Modifying a global variable's usage requires checking all functions.
  • Lack of Data Hiding: No mechanism to restrict access to data, leading to accidental modifications and security risks.
  • Code Duplication: Similar logic often repeated across functions due to lack of inheritance or reuse mechanisms.
// Procedure-oriented programming example (C)
int global_data = 10; // Global variable - accessible everywhere

void add() {
    global_data += 5; // Can be modified anywhere
}

void subtract() {
    global_data -= 3; // Uncontrolled access
}

int main() {
    add();
    subtract();
    printf("%d", global_data); // Hard to track changes
    return 0;
}
💡 Key insight: Procedure-oriented programming works well for small, simple programs but becomes difficult to manage as software grows in size and complexity.

1.2 Introduction to Object-Oriented Programming, Advantages and Disadvantages

Object-Oriented Programming (OOP) is a programming paradigm that organizes code around objects, which combine data and behaviors, to model real-world entities.

Introduction to OOP

  • Definition: OOP uses objects (instances of classes) that encapsulate data (attributes) and functions (methods).
  • Example: A "Car" class with attributes (speed, color) and methods (drive, stop).
  • Languages: Java, C++, Python, C#, JavaScript (ES6+), Ruby.
// Object-oriented programming example (Java)
public class Car {
    private int speed; // Encapsulated data
    private String color;

    public Car(String color) {
        this.color = color;
        this.speed = 0;
    }

    public void drive() {
        speed += 10;
    }

    public int getSpeed() {
        return speed;
    }
}

Disadvantages of OOP

  • Complexity: OOP can be overkill for simple programs. Example: A small script may not need classes.
  • Learning Curve: Requires understanding concepts like inheritance and polymorphism. Example: Beginners may struggle with abstract classes.
  • Overhead: OOP programs may use more memory and processing due to object creation. Example: Instantiating many objects in Java can be resource-intensive.
  • Design Challenges: Poorly designed class hierarchies can lead to complexity. Example: Overusing inheritance can create tangled dependencies.
📦 Key insight: OOP provides a powerful framework for building complex, maintainable software. While it has a learning curve, the benefits for large-scale development far outweigh the costs.

1.3 Features and Concepts of Object-Oriented Programming

OOP is built on core features and concepts that enable robust and flexible software design.

Core OOP Concepts

  • Objects: Instances of classes that combine data and methods.
    Student s1 = new Student(); // Object creation
    s1.name = "Alice";
    s1.register();
  • Classes: Blueprints for creating objects.
    class Student {
        String name;
        int id;
        void register() { ... }
    }
  • Encapsulation: Restricting access to an object's data through access modifiers (private, public) and providing controlled access via methods.
  • Inheritance: A class (child) inherits properties and methods from another class (parent).
    class SportsCar extends Car {
        void turboBoost() { ... }
    }
  • Polymorphism: Objects of different classes can be treated as objects of a common superclass, or methods can behave differently based on context.
    Shape s1 = new Circle();
    Shape s2 = new Rectangle();
    s1.draw(); // Draws circle
    s2.draw(); // Draws rectangle
  • Abstraction: Hiding complex implementation details and exposing only necessary features.
    interface Phone {
        void call(); // Implementation hidden
    }

1.4 Basic Concept of OOP

The basic concepts of OOP provide a framework for designing software around real-world entities.

Object and Class

  • Class: Defines the structure and behavior of objects.
  • Object: An instance of a class.
// Class and Object Example
class Employee {
    private String name;
    private double salary;

    public Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }

    public double calculateBonus() {
        return salary * 0.1;
    }
}

Employee emp = new Employee("Alice", 50000);

Encapsulation

  • Combines data and methods into a single unit (class).
  • Restricts access to ensure data integrity.
  • Example: In C++, private data members like "age" are accessed via public getters and setters.

Inheritance

  • Enables code reuse by allowing a class to inherit attributes and methods from another.
  • Example: A "Manager" class inherits from "Employee" and adds a department attribute.

Polymorphism

  • Allows flexibility through method overriding or overloading.
  • Example: A "Vehicle" class's start() method is overridden differently in "Car" and "Bicycle".

Abstraction

  • Simplifies complex systems by focusing on essential features.
  • Example: An "Animal" abstract class defines eat() but leaves implementation to "Dog" or "Cat".
