Unit 8: Generics

Advantages · generic classes · generic methods · generic constructors · polymorphism & wildcards

8.1 Advantages of Using Generics

Generics in Java, introduced in Java 5, allow classes, interfaces, and methods to operate on parameterized types, providing type safety and flexibility. They enable developers to write reusable code that works with different data types without sacrificing compile-time type checking.

🛡️ Type Safety
Generics ensure that only the specified type is used, preventing runtime errors like ClassCastException.
♻️ Code Reusability
Generic classes and methods can work with any data type, reducing code duplication.
⬇️ Elimination of Casts
Generics remove the need for explicit type casting when retrieving objects from collections.
🔍 Compile-Time Checking
Type errors are caught at compile-time rather than runtime, improving reliability.
// Without Generics (requires casting)
ArrayList list = new ArrayList();
list.add("Hello");
String str = (String) list.get(0); // Explicit cast

// With Generics (no casting needed)
ArrayList genericList = new ArrayList<>();
genericList.add("Hello");
String genericStr = genericList.get(0); // No cast needed
💡 Key insight: Generics shift type checking to compile time, making code safer, more readable, and more maintainable. They are especially useful with collections.

8.2 Generic Classes

A generic class is a class that can operate on a parameterized type, defined using type parameters in angle brackets (<T>). The type parameter acts as a placeholder for the actual type used when the class is instantiated.

Syntax

public class ClassName<T> {
    private T field;
    public void set(T value) { this.field = value; }
    public T get() { return field; }
}
// Generic Class Example
public class Box<T> {
    private T content;

    public void setContent(T content) {
        this.content = content;
    }

    public T getContent() {
        return content;
    }

    public static void main(String[] args) {
        Box<Integer> intBox = new Box<>();
        intBox.setContent(123);
        System.out.println("Integer Box: " + intBox.getContent());

        Box<String> strBox = new Box<>();
        strBox.setContent("Hello");
        System.out.println("String Box: " + strBox.getContent());
    }
}

Multiple Type Parameters

public class Pair<K, V> {
    private K key;
    private V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() { return key; }
    public V getValue() { return value; }
}

Pair<String, Integer> pair = new Pair<>("Age", 25);

8.3 Generic Methods

Generic methods are methods that introduce their own type parameters, independent of the class's type parameters. They are defined with a type parameter before the return type.

Syntax

public <T> returnType methodName(T parameter) {
    // method body
}
// Generic Method Example
public class GenericMethodExample {
    // Generic method
    public static <T> void printArray(T[] array) {
        for (T element : array) {
            System.out.print(element + " ");
        }
        System.out.println();
    }

    public static void main(String[] args) {
        Integer[] intArray = {1, 2, 3};
        String[] strArray = {"A", "B", "C"};

        printArray(intArray); // Output: 1 2 3
        printArray(strArray); // Output: A B C
    }
}
// Generic method with return type
public static <T> T getMiddle(T... items) {
    return items[items.length / 2];
}

String middle = getMiddle("A", "B", "C", "D", "E"); // "C"

8.4 Generic Constructors

Generic constructors allow constructors to use type parameters, either from the class or independently. They are useful when the constructor needs to handle different types dynamically.

// Generic Constructor Example
public class GenericConstructor<T> {
    private T data;

    // Generic constructor with independent type parameter
    public <U> GenericConstructor(U data) {
        this.data = (T) data; // Cast required if U != T
        System.out.println("Data: " + data);
    }

    public T getData() {
        return data;
    }

    public static void main(String[] args) {
        GenericConstructor<String> strObj =
            new GenericConstructor<>("Test");
        System.out.println("Stored: " + strObj.getData());

        GenericConstructor<Integer> intObj =
            new GenericConstructor<>(100);
        System.out.println("Stored: " + intObj.getData());
    }
}
// Better approach: Constructor with same type as class
public GenericConstructor(T data) {
    this.data = data;
}

GenericConstructor<String> obj = new GenericConstructor<>("Hello");

8.5 Polymorphism in Generics

Polymorphism in generics allows generic types to work with class hierarchies, using bounded type parameters to restrict the types that can be used.

Upper Bounded Types

  • Restrict the type to a class or its subclasses using <T extends Class>.
  • Example: <T extends Number> allows Integer, Double, Float, etc.
// Upper Bounded Generic Method
public static <T extends Number> double sum(T num1, T num2) {
    return num1.doubleValue() + num2.doubleValue();
}

System.out.println(sum(10, 20)); // 30.0
System.out.println(sum(10.5, 20.5)); // 31.0

Wildcards (?) for Polymorphism

  • Unbounded Wildcard: <?> — Any type.
  • Upper Bounded Wildcard: <? extends Class> — Class or subclasses.
  • Lower Bounded Wildcard: <? super Class> — Class or superclasses.
// Wildcard Example - Upper Bound
import java.util.*;

public static void printList(List<? extends Number> list) {
    for (Number num : list) {
        System.out.print(num + " ");
    }
    System.out.println();
}

List<Integer> intList = Arrays.asList(1, 2, 3);
List<Double> doubleList = Arrays.asList(1.1, 2.2, 3.3);

printList(intList); // 1 2 3
printList(doubleList); // 1.1 2.2 3.3

Bounded Type Parameters Summary

TypeSyntaxUsage
Upper Bound<T extends Class>T must be Class or subclass
Upper Bound Wildcard<? extends Class>Any subclass of Class
Lower Bound Wildcard<? super Class>Any superclass of Class
Unbounded Wildcard<?>Any type
// Lower Bound Wildcard Example
public static void addNumbers(List<? super Integer> list) {
    list.add(10);
    list.add(20);
}

List<Number> numList = new ArrayList<>();
addNumbers(numList); // Works because Number is superclass of Integer
🔑 Key insight: Bounded types and wildcards enable flexible, type-safe polymorphic behavior in generic code. Use upper bounds for reading, lower bounds for writing, and PECS (Producer Extends, Consumer Super) principle.
📘 Unit 8 summary
Generics provide type safety and reusability through parameterized types. Key concepts include generic classes, methods, constructors, and bounded types.
🔑 Key takeaways
• Advantages: type safety, reusability, no casts.
• Generic classes: <T> type parameter.
• Generic methods: <T> before return type.
• Generic constructors: independent type parameters.
• Upper bounds: <T extends Class>.
• Wildcards: ? (unbounded), ? extends (upper), ? super (lower).
• PECS: Producer Extends, Consumer Super.
