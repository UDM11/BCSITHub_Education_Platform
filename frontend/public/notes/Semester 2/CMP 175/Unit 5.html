5.1 Introduction to Exception

An exception in Java is an event that disrupts the normal flow of a program's execution. It occurs during runtime due to unexpected conditions, such as invalid input, file not found, or division by zero. Exception handling allows a program to detect and respond to these issues gracefully, ensuring robustness and preventing crashes.

⚠️ What is an Exception?
An exception is an event that interrupts the normal flow of program execution. It represents an abnormal condition that occurs during runtime.
🛡️ Why Handle Exceptions?
To build robust applications that can gracefully recover from errors, provide meaningful error messages, and prevent program crashes.

5.2 Errors in Java Program

Errors represent serious problems that a Java program cannot reasonably recover from. They are typically caused by issues outside the program's control, such as hardware failures or JVM issues.

Types of Errors

  • OutOfMemoryError: Occurs when the JVM runs out of memory.
  • StackOverflowError: Caused by excessive recursion leading to stack overflow.
  • VirtualMachineError: Indicates JVM issues, such as corrupted internal data.
  • NoClassDefFoundError: When a class definition cannot be found.
// StackOverflowError Example
public class ErrorExample {
    public static void recursiveMethod() {
        recursiveMethod(); // Infinite recursion
    }

    public static void main(String[] args) {
        recursiveMethod(); // Throws StackOverflowError
    }
}
⚠️ Key insight: Errors are not meant to be caught or handled in typical applications. They indicate critical issues that require intervention at the system level.

5.3 Types of Exceptions

Exceptions in Java are categorized into two types: checked and unchecked exceptions.

Checked Exceptions

  • Definition: Checked at compile-time. The programmer must handle them using try-catch or declare using throws.
  • Examples: IOException, SQLException, FileNotFoundException, ClassNotFoundException.
  • Required Action: Either handle with try-catch or declare with throws.

Unchecked Exceptions (RuntimeException)

  • Definition: Occur at runtime and are not checked at compile-time.
  • Examples: NullPointerException, ArithmeticException, ArrayIndexOutOfBoundsException, IllegalArgumentException.
  • Required Action: Handling is optional (but recommended).

5.4 Exception Handling Mechanism

Java provides a robust mechanism to handle exceptions using the following keywords:

Try-Catch-Finally

  • try: Encloses code that might throw an exception.
  • catch: Handles the exception thrown in the try block.
  • finally: Executes code regardless of whether an exception occurs (cleanup).

Throw and Throws

  • throw: Explicitly throws an exception.
  • throws: Declares exceptions that a method might throw.
// Exception Handling Example
public class ExceptionHandlingDemo {
    public static void main(String[] args) {
        try {
            int result = 10 / 0; // ArithmeticException
        } catch (ArithmeticException e) {
            System.out.println("Error: " + e.getMessage());
        } finally {
            System.out.println("Cleanup in finally block.");
        }
    }
}

// throw and throws Example
public void validateAge(int age) throws IllegalArgumentException {
    if (age < 18) {
        throw new IllegalArgumentException("Age must be 18 or above.");
    }
}

Multi-catch (Java 7+)

try {
    // code that may throw multiple exceptions
} catch (IOException | SQLException e) {
    System.out.println("I/O or SQL error: " + e.getMessage());
}

5.6 User-Defined Exception in Java

User-defined exceptions are custom exceptions created by extending the Exception class (for checked exceptions) or RuntimeException (for unchecked exceptions). They allow developers to define specific error conditions for their application.

Creating a Custom Exception

  • Extend Exception for checked exceptions.
  • Extend RuntimeException for unchecked exceptions.
  • Provide constructors that call super(message).
// User-defined Exception Example
public class InsufficientBalanceException extends Exception {
    public InsufficientBalanceException(String message) {
        super(message);
    }
}

public class BankAccount {
    private double balance;

    public BankAccount(double initialBalance) {
        this.balance = initialBalance;
    }

    public void withdraw(double amount) throws InsufficientBalanceException {
        if (amount > balance) {
            throw new InsufficientBalanceException(
                "Insufficient balance. Available: " + balance
            );
        }
        balance -= amount;
    }

    public static void main(String[] args) {
        BankAccount account = new BankAccount(100.0);
        try {
            account.withdraw(150.0);
        } catch (InsufficientBalanceException e) {
            System.out.println("Transaction failed: " + e.getMessage());
        }
    }
}
// Unchecked Custom Exception
public class InvalidAgeException extends RuntimeException {
    public InvalidAgeException(String message) {
        super(message);
    }
}
🔧 Key insight: User-defined exceptions make your code more readable and maintainable by providing meaningful error messages specific to your application's domain.
📘 Unit 5 summary
Exception handling in Java provides a robust mechanism to handle runtime errors using try-catch-finally, throw, and throws. Built-in and user-defined exceptions enable graceful error recovery.
🔑 Key takeaways
• Exceptions: abnormal events during program execution.
• Errors: serious issues (OutOfMemory, StackOverflow).
• Checked vs Unchecked: compile-time vs runtime.
• Try-catch-finally: handle exceptions and cleanup.
• throw: explicitly throw exceptions.
• throws: declare exceptions in method signature.
• Built-in exceptions: Arithmetic, NullPointer, IOException, etc.
• User-defined: extend Exception or RuntimeException.
