8.1 Introduction

Searching is the process of finding a specific element in a collection of data. It is a fundamental operation in computer science, used in applications like databases, file systems, and information retrieval. The efficiency of a search algorithm depends on the data structure and the organization of the data.

🔍 What is Searching?
Finding a specific element (target) within a data structure. Used in databases, file systems, and everyday applications.
📊 Key Factors
Data organization (sorted/unsorted), data structure (array, tree, hash table), and algorithm efficiency.

Applications

  • Database query optimization.
  • File system navigation.
  • Information retrieval in search engines.
  • Symbol table lookup in compilers.
  • Spell checkers and dictionary lookups.

8.2 Searching Techniques

Sequential Search (Linear Search)

  • Approach: Checks each element sequentially until the target is found or the list ends.
  • Time Complexity: O(n)
  • Space Complexity: O(1)
  • Best For: Unsorted or small datasets.
int sequentialSearch(int arr[], int n, int target) {
    for (int i = 0; i < n; i++) {
        if (arr[i] == target) return i;
    }
    return -1;
}

Binary Search

  • Approach: Divides sorted array in half at each step, comparing target with middle element.
  • Time Complexity: O(log n)
  • Space Complexity: O(1)
  • Best For: Sorted arrays with few insertions/deletions.
int binarySearch(int arr[], int n, int target) {
    int left = 0, right = n - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (arr[mid] == target) return mid;
        if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}

Tree Search (BST)

  • Approach: Searches a binary search tree by comparing target with node values.
  • Time Complexity: O(log n) average, O(n) worst case.
  • Space Complexity: O(1) iterative, O(log n) recursive.
  • Best For: Dynamic data with frequent insertions/deletions.
Node* search(Node* root, int target) {
    if (root == NULL || root->data == target) return root;
    if (target < root->data)
        return search(root->left, target);
    return search(root->right, target);
}

8.3 Hashing

Hashing is a technique that maps data to a fixed-size array (hash table) using a hash function, enabling fast retrieval of elements.

Hash Functions

  • Characteristics of Good Hash Functions:
    • Uniform Distribution: Distributes keys evenly across the hash table.
    • Deterministic: Same input always produces the same output.
    • Efficiency: Computes hash value quickly.
    • Minimal Collisions: Reduces the likelihood of different keys mapping to the same index.
  • Types of Hash Functions:
    • Division Method: h(k) = k % m (m is table size, preferably prime).
    • Multiplication Method: h(k) = floor(m * (k * A % 1)), where 0 < A < 1.
    • Mid-Square Method: Square the key, take middle digits, and apply modulo.
    • Folding Method: Divide the key into parts, sum them, and apply modulo.

Hash Tables

  • Definition: Data structure that stores key-value pairs using a hash function.
  • Applications:
    • Databases (indexing).
    • Caches (frequently accessed data).
    • Symbol tables (compilers).
    • Dictionary implementations.
// Hash Table Implementation
typedef struct {
    int* table;
    int size;
} HashTable;

HashTable* createHashTable(int size) {
    HashTable* ht = (HashTable*)malloc(sizeof(HashTable));
    ht->size = size;
    ht->table = (int*)calloc(size, sizeof(int));
    return ht;
}

int hash(HashTable* ht, int key) {
    return key % ht->size;
}

void insert(HashTable* ht, int key) {
    int index = hash(ht, key);
    ht->table[index] = key;
}

8.4 Collision Resolution Techniques

A collision occurs when multiple keys hash to the same index. Common resolution techniques include:

Open Addressing

  • All elements are stored in the hash table itself.
  • Probes for the next available slot.
  • Types: Linear Probing, Quadratic Probing, Double Hashing.

Chaining

  • Each slot contains a linked list of all keys that hash to that index.
  • Simple to implement and handles collisions efficiently.
Collision Resolution:
Open Addressing:  [Index] → [Key] → [Key] → [Key] (same slot with probing)
Chaining:          [Index] → [Key] → [Key] → [Key] (linked list)

8.5 Hashing with Open Addressing

Linear Probing

  • If collision at h(k), check h(k)+1, h(k)+2, ... (mod m).
  • Advantage: Simple to implement.
  • Disadvantage: Primary clustering (long runs of occupied slots).
void insertLinear(HashTable* ht, int key) {
    int index = key % ht->size;
    while (ht->table[index] != 0) {
        index = (index + 1) % ht->size;
    }
    ht->table[index] = key;
}

Quadratic Probing

  • Uses quadratic function: h(k, i) = (h(k) + i²) % m.
  • Advantage: Reduces primary clustering.
  • Disadvantage: Secondary clustering possible.
void insertQuadratic(HashTable* ht, int key) {
    int index = key % ht->size;
    int i = 0;
    while (ht->table[index] != 0) {
        i++;
        index = (key % ht->size + i * i) % ht->size;
    }
    ht->table[index] = key;
}

Double Hashing

  • Uses second hash function: h(k, i) = (h₁(k) + i * h₂(k)) % m.
  • Advantage: Minimizes clustering.
  • Disadvantage: More computationally expensive.
int hash2(int key, int size) {
    return 1 + (key % (size - 1));
}

void insertDoubleHash(HashTable* ht, int key) {
    int index = key % ht->size;
    int i = 0;
    while (ht->table[index] != 0) {
        i++;
        index = (key % ht->size + i * hash2(key, ht->size)) % ht->size;
    }
    ht->table[index] = key;
}

8.6 Hashing with Chaining

In chaining, each hash table slot contains a linked list to store all keys that hash to that index. Collisions are resolved by adding the key to the linked list.

Advantages

  • Handles collisions simply.
  • No clustering issues.
  • Table can grow beyond initial size.
// Chaining Implementation
typedef struct Node {
    int data;
    struct Node* next;
} Node;

typedef struct {
    Node** table;
    int size;
} HashTableChaining;

void insertChaining(HashTableChaining* ht, int key) {
    int index = key % ht->size;
    Node* newNode = createNode(key);
    newNode->next = ht->table[index];
    ht->table[index] = newNode;
}

8.7 Rehashing

Rehashing is the process of resizing a hash table (usually doubling its size) and reinserting all existing keys when the load factor (ratio of elements to table size) exceeds a threshold. This reduces collisions and maintains performance.

When to Rehash

  • Load factor > 0.7 (typical threshold).
  • Performance degrades due to too many collisions.
// Rehashing Implementation
void rehash(HashTableChaining* ht) {
    Node** oldTable = ht->table;
    int oldSize = ht->size;
    ht->size *= 2;
    ht->table = (Node**)calloc(ht->size, sizeof(Node*));
    for (int i = 0; i < oldSize; i++) {
        Node* current = oldTable[i];
        while (current != NULL) {
            Node* next = current->next;
            insertChaining(ht, current->data);
            free(current);
            current = next;
        }
    }
    free(oldTable);
}

Choosing the Right Technique

  • Unsorted data: Sequential Search (or sort first for better performance).
  • Sorted static data: Binary Search.
  • Dynamic data with frequent insertions/deletions: BST or Hashing.
  • Fast lookup requirements: Hashing with good collision resolution.
🔍 Key insight: No single search technique is optimal for all scenarios. The choice depends on data size, organization, update frequency, and performance requirements.
📘 Unit 8 summary
Searching finds elements in data structures. Techniques include sequential, binary, tree search, and hashing. Hashing offers O(1) average time with proper collision resolution.
🔑 Key takeaways
• Sequential search: O(n) for unsorted data.
• Binary search: O(log n) for sorted arrays.
• Tree search: O(log n) for balanced BSTs.
• Hashing: O(1) average with good hash function.
• Collision resolution: chaining, open addressing (linear, quadratic, double hashing).
• Rehashing maintains performance as table grows.
