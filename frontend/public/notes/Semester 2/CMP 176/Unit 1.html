Unit 1: Introduction to Data Structure

Definition · classification · ADT · algorithm · analysis · design · performance

1.1 Introduction

Data structures are specialized formats for organizing, storing, and managing data to enable efficient access and manipulation. They form the backbone of computer algorithms, allowing programs to handle data effectively for tasks like searching, sorting, and processing. Choosing the right data structure significantly impacts a program's performance and efficiency.

📊 What are Data Structures?
Ways to organize and store data so it can be used efficiently. They define the relationship between data elements and provide operations to access and modify them.
🎯 Why are they Important?
The right data structure can dramatically improve algorithm performance, reduce memory usage, and make code more maintainable and scalable.

Real-World Analogy

  • Library Catalog: Books organized by author, title, or subject (like different data structures).
  • Grocery List: Simple list vs. categorized list (like arrays vs. trees).
  • File System: Hierarchical organization (like trees).

1.2 Definition

A data structure is a way of organizing data in a computer so that it can be used efficiently. It defines the relationship between data elements and provides operations to access and modify them.

Key Characteristics

  • Organization: How data elements are arranged and related.
  • Operations: What operations can be performed (insert, delete, search, traverse).
  • Performance: Time and space complexity of operations.

Examples

  • Arrays: Contiguous memory locations with index-based access.
  • Linked Lists: Nodes connected by pointers, dynamic size.
  • Stacks: LIFO (Last In, First Out) structure.
  • Queues: FIFO (First In, First Out) structure.
  • Trees: Hierarchical structure with root and child nodes.
  • Graphs: Network of nodes connected by edges.
// Example: Array in C
int arr[5] = {10, 20, 30, 40, 50};
printf("%d", arr[2]); // Access element at index 2: 30

Classification Categories

  • Primitive Data Structures: Basic data types provided by programming languages (int, float, char, boolean).
  • Non-Primitive Data Structures: Derived from primitive types:
    • Linear: Elements arranged sequentially (Arrays, Linked Lists, Stacks, Queues)
    • Non-Linear: Elements arranged hierarchically or in networks (Trees, Graphs)
  • Static vs Dynamic:
    • Static: Fixed size (e.g., arrays)
    • Dynamic: Can grow/shrink during execution (e.g., linked lists)

1.4 Abstract Data Type (ADT)

An Abstract Data Type (ADT) is a logical description of how data is viewed and the operations that can be performed, without specifying implementation.

Key Concepts

  • Abstraction: Hides implementation details from the user.
  • Encapsulation: Bundles data and operations together.
  • Interface: Defines what operations are available.

Example: Stack ADT

// Stack ADT Operations
// push(data): Add an element to the top

// isEmpty(): Check if stack is empty

1.6 Algorithm

An algorithm is a finite set of well-defined instructions to solve a specific problem. It must be clear, unambiguous, and guaranteed to terminate.

Characteristics of a Good Algorithm

  • Finiteness: Must terminate after a finite number of steps.
  • Definiteness: Each step must be precisely defined.
  • Input: Has zero or more inputs.
  • Output: Has one or more outputs.
  • Effectiveness: Each step must be doable.
// Example: Bubble Sort Algorithm in C
void bubbleSort(int arr[], int n) {
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}

1.7 Analysis of Algorithm

Algorithm analysis evaluates the efficiency of an algorithm in terms of time and space requirements.

Time Complexity

  • Definition: The amount of time taken by an algorithm to run as a function of input size.
  • Asymptotic Notations:
    • O(n) - Big O: Upper bound (worst case)
    • Ω(n) - Big Omega: Lower bound (best case)
    • Θ(n) - Big Theta: Tight bound (average case)

Space Complexity

  • Definition: The amount of memory used by an algorithm as a function of input size.
  • Components:
    • Fixed Space: Constants, variables, and code.
    • Variable Space: Depends on input size (e.g., arrays, recursion stack).

1.8 Design of Algorithm

Algorithm design involves creating efficient solutions to problems using various strategies.

Common Design Approaches

1. Incremental (Iterative)

  • Builds solution step-by-step.
  • Examples: Insertion Sort, Selection Sort.
// Insertion Sort - Incremental
void insertionSort(int arr[], int n) {
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;
    }
}

2. Divide and Conquer

  • Divide problem into smaller sub-problems.
  • Solve sub-problems recursively.
  • Combine solutions.
  • Examples: Merge Sort, Quick Sort, Binary Search.
// Merge Sort - Divide and Conquer
void mergeSort(int arr[], int l, int r) {
    if (l < r) {
        int m = l + (r - l) / 2;
        mergeSort(arr, l, m);
        mergeSort(arr, m + 1, r);
        merge(arr, l, m, r);
    }
}

3. Greedy

  • Makes locally optimal choices at each step.
  • Examples: Dijkstra's algorithm, Huffman coding.

4. Dynamic Programming

  • Breaks problem into overlapping subproblems.
  • Stores results to avoid recomputation.
  • Examples: Fibonacci, Knapsack problem.

1.9 Performance Analysis and Measurement

Performance analysis evaluates algorithms through theoretical analysis and empirical testing.

Space Complexity Analysis

  • Fixed Space: Constants, simple variables, program code.
  • Variable Space: Depends on input size (arrays, recursion stack, dynamic allocation).

Time Complexity Analysis

  • Best Case: Minimum time (e.g., already sorted array).
  • Average Case: Expected time for random input.
  • Worst Case: Maximum time (e.g., reverse sorted array).
// Linear Search - Time: O(n), Space: O(1)
int linearSearch(int arr[], int n, int x) {
    for (int i = 0; i < n; i++) {
        if (arr[i] == x)
            return i;
    }
    return -1;
}
// Best: O(1), Average: O(n), Worst: O(n)
// Binary Search - Time: O(log n), Space: O(1)
int binarySearch(int arr[], int l, int r, int x) {
    while (l <= r) {
        int m = l + (r - l) / 2;
        if (arr[m] == x) return m;
        if (arr[m] < x) l = m + 1;
        else r = m - 1;
    }
    return -1;
}
// Best: O(1), Average: O(log n), Worst: O(log n)
// Recursive Fibonacci - Time: O(2ⁿ), Space: O(n)
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
// Highly inefficient for large n due to exponential time
📊 Key insight: Performance analysis helps choose the right algorithm and data structure for a given problem. Understanding time and space complexity is essential for writing efficient code.
