1.1 Course Syllabus & Overview

Project I (PRJ 181) is a milestone practical course in the First Year, Second Semester of the Bachelor of Computer System and Information Technology (BCSIT) program under the Pokhara University curriculum. This course is designed to transition students from theoretical programming to functional, real-world web application engineering.

📊 Course Parameters:
• Course Code: PRJ 181
• Course Title: Project I
• Credits: 2 [Hrs]
• Nature: Lab-oriented Project Work
• Total Hours: 32 lectures equivalent of lab counseling.
🎯 Primary Objectives:
• Master structural markup using HTML5 semantic elements.
• Gain layout precision using CSS Box Model, Flexbox, and Grid.
• Implement dynamic user experiences via vanilla JavaScript/jQuery DOM manipulation.
• Learn asynchronous network requests (AJAX/Fetch) and JSON integration.

Students begin by learning how to structure document trees cleanly, followed by applying advanced CSS for layout alignment and visual fidelity. JavaScript is then introduced to capture events, handle user actions, validate forms, and request data from API endpoints without reloading the document.

1.2 Project Academic Timeline & Evaluation System

The project requires systematic progress across 48 days of development. The university implements a progressive marking scheme to evaluate consistency:

Milestone Timeline (Days) Expected Deliverables Marks

Proposal Defense Days 6 - 10 Printed project proposal draft, slide presentation defending scope, methodology, and Gantt chart. 5 Marks

1.4 Prescribed Proposal Content Flow

The project proposal is a formal document serving as the development roadmap. It must follow this exact flow:

  1. Cover Page: Title, course details, program code, submission metadata, and university logo.
  2. Introduction: Background context explaining the business utility of the website.
  3. Problem Statement: Clearly identify the challenges or inefficiencies of existing systems that your project will address.
  4. Objectives of the Study:
    • General Objective: The high-level ultimate goal (e.g., "To develop a responsive booking application").
    • Specific Objectives: Measurable development targets (e.g., "To create dynamic form validation", "To implement slider controls").
  5. Methodology:
    • Requirement Identification: Defining target users and system behaviors.
    • Study of Existing Systems: Brief review of similar solutions in the market.
    • Requirement Collection: Compiling technical requirements.
    • Feasibility Study: Quick analysis on Technical, Operational, and Economic viability.
    • High-Level Design: Flowcharts representing user interaction logic.
  6. Gantt Chart: Visually tracking development progress over the 48-day project timeline.
  7. Expected Outcome: Summary of the final deliverables.
  8. References: Citing textbooks, articles, or online documentation.

1.5 Semantic HTML5 Tags Reference Guide

Semantic elements clearly describe their meaning to both the browser and the developer. This is a core component of the Project I syllabus:

Tag Semantic Purpose Code Context Example
<header> Contains introductory content, site title, or main navigation. <header><nav>...</nav></header>
<main> Specifies the dominant content area of the document body. <main><article>...</article></main>
<section> Defines a thematic grouping of content, typically with a heading. <section><h2>Scope</h2>...</section>
<article> Represents self-contained, independent, reusable compositions. <article><p>Project Phase details...</p></article>
<aside> Contains tangentially related content like sidebars or Callouts. <aside><h4>Quick Tip</h4></aside>
<footer> Defines meta information, copyright notes, or contact info. <footer><p>© 2026 BCSIT</p></footer>

1.6 CSS Box Model & Fluid Grid Layouts

Understanding the Box Model is crucial to creating layouts without overlapping errors. Every element is represented as a rectangular box comprising content, padding, border, and margin: 

┌────────────────────────────────────────────────────────┐
│                        MARGIN                          │
│   ┌────────────────────────────────────────────────┐   │
│   │                    BORDER                      │   │
│   │   ┌────────────────────────────────────────┐   │   │
│   │   │                PADDING                 │   │   │
│   │   │   ┌────────────────────────────────┐   │   │   │
│   │   │   │            CONTENT             │   │   │   │
│   │   │   │        (Width × Height)        │   │   │   │
│   │   │   └────────────────────────────────┘   │   │   │
│   │   └────────────────────────────────────────┘   │   │
│   └────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────┘

For modern fluid grids, box-sizing: border-box; ensures that padding and borders are calculated within the specified width rather than expanding it.

Fluid Grid Layout Implementation Code:

/* Global Box Model Settings */
* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}

/* Responsive Grid Layout */
.grid-layout {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(300px, 1fr));
    gap: 1.5rem;
    padding: 1rem;
}

/* Card Styling with CSS Variables */
.grid-layout .card {
    background: #ffffff;
    padding: 1.5rem;
    border-radius: 12px;
    box-shadow: 0 4px 10px rgba(0, 0, 0, 0.05);
    border: 1px solid #e3ecf5;
}

1.7 Dynamic Interactivity & Semantic Form Layout

To fulfill Phase 1 milestones, teams must code semantically compliant form validation layouts. The form uses semantic elements for inputs, choices, and buttons:

<!-- Responsive Registration Form layout -->
<form id="registrationForm" class="form-grid" novalidate>
    <div class="form-group">
        <label for="username">Username</label>
        <input type="text" id="username" name="username" required placeholder="Enter username">
    </div>
    <div class="form-group">
        <label for="email">Email Address</label>
        <input type="email" id="email" name="email" required placeholder="name@domain.com">
    </div>
    <button type="submit" class="submit-btn">Register Team</button>
</form>

Using the novalidate attribute on forms allows JavaScript to intercept the submit action and execute custom regular expression (regex) verification before data is processed.

1.8 Document Formatting Guidelines

To maintain uniformity across all project documentation, the university mandates strict guidelines for reports:

  • Page Size: Standard A4 paper format (210mm x 297mm).
  • Page Margins:
    • Top: 1.0 inch (2.54 cm)
    • Bottom: 1.0 inch (2.54 cm)
    • Left: 1.25 inches (3.17 cm) to allow for binding
    • Right: 1.0 inch (2.54 cm)
  • Typography:
    • Primary Font: Times New Roman or Segoe UI
    • Main Heading size: 14pt (Bold, Centered)
    • Sub-heading size: 12pt (Bold)
    • Body Text size: 12pt (Normal, Justified)
  • Paragraph Settings: Line spacing of exactly 1.5, with 6pt spacing after paragraphs.
📝 Binding Note: The final report copy must be spiral bound (for mid-term drafts) or hardbound with a dark blue cover (for the final defense submission).
