8.1 Network Management and SNMP

What is Network Management?

Network management is the process of administering, managing, and maintaining computer networks. The ISO defines five functional areas of network management (FCAPS):

  • Fault Management: Detecting, isolating, and resolving network problems.
  • Configuration Management: Tracking and controlling network configurations, devices, and software updates.
  • Accounting Management: Tracking network utilization statistics to bill users or allocate resources.
  • Performance Management: Monitoring network metrics (throughput, latency, packet loss) to maintain service quality.
  • Security Management: Controlling access to network resources and protecting data.

SNMP (Simple Network Management Protocol)

SNMP is an application layer protocol used to monitor and manage network devices (routers, switches, servers) over **UDP Port 161 (polling)** and **UDP Port 162 (traps)**.

SNMP Architecture Components

  ┌────────────────────────────────────────────────────────┐
  │         Network Management Station (NMS / Manager)     │
  └───────────────────────────┬───▲────────────────────────┘
            Get / Set request │   │ Trap notification
                              ▼   │
  ┌───────────────────────────┴───┴────────────────────────┐
  │                  Managed Device (Agent)                │
  │  ┌──────────────────────────────────────────────────┐  │
  │  │   MIB (Management Information Base)              │  │
  │  │   └─ OID: 1.3.6.1.2.1.1.1.0 (System Description) │  │
  │  └──────────────────────────────────────────────────┘  │
  └────────────────────────────────────────────────────────┘
  • SNMP Manager (NMS): A central system that runs monitoring software to query agents and collect reports.
  • SNMP Agent: Software running on the managed device that monitors local parameters and responds to queries from the manager.
  • MIB (Management Information Base): A hierarchical, structured database on the agent defining what variables (parameters) the manager can query or configure.
  • OID (Object Identifier): Unique dotted numbers that identify parameters in the MIB hierarchy (e.g., 1.3.6.1.2.1.1.1.0 represents System Description).

SNMP Commands

  • GetRequest: Manager retrieves a value from the agent's MIB.
  • GetNextRequest: Manager retrieves the next value in the MIB table.
  • SetRequest: Manager modifies a configuration value on the agent.
  • Response: Agent returns requested values to the manager.
  • Trap: Agent sends an unsolicited alert to the manager informing them of a critical event (e.g., interface down, high CPU load).

8.2 Data Security and Network Attacks

Key Risks in Data Security

  • Data Breaches: Unauthorized access to sensitive, private data.
  • Data Loss: Accidental deletion or corruption of critical business files.
  • Data Alteration: Malicious tampering with data during transit or in storage.
  • Identity Theft: Stealing user credentials to impersonate legitimate personnel.

Types of Network Attacks

Attacks are classified as passive (monitoring data) or active (modifying data/services):

1. Passive Attacks

  • Eavesdropping / Packet Sniffing: Capturing packets traversing the network using tools like Wireshark to steal unencrypted credentials or sensitive information.
  • Traffic Analysis: Monitoring communication patterns (frequency, volume, locations) to deduce information.

2. Active Attacks

  • DoS / DDoS (Denial of Service): Overwhelming network devices or servers with massive volumes of fake traffic (e.g., SYN floods), crashing services to make them unavailable to legitimate users.
  • Man-in-the-Middle (MitM): An attacker positions themselves between two communicating hosts to hijack sessions, read data, or inject malicious payloads.
  • IP Spoofing: Forging the source IP address in packet headers to bypass access control list (ACL) rules.
  • Phishing: Sending deceptive emails disguised as trusted entities to trick users into divulging passwords or credit card numbers.

Countermeasures

  • Use **strong encryption** (HTTPS, SSH, SFTP, IPsec) for all communications.
  • Implement **Multifactor Authentication (MFA)** to secure access.
  • Regular **security updates and patching** of systems.
  • Maintain **offline, encrypted backups** of critical data.
  • Run regular **penetration testing** and vulnerability scans.

8.3 Cryptography (Symmetric vs. Asymmetric)

Cryptography is the practice of securing communication in the presence of adversaries by converting plain text into unreadable cipher text.

Symmetric Key Cryptography

Uses the **same single secret key** for both encryption and decryption. Both sender and receiver must agree on and secure this key before starting communication.

  • Encryption: $C = E_k(P)$
  • Decryption: $P = D_k(C)$
  • Advantages: Extremely fast, computationally light, suitable for bulk data transfer.
  • Disadvantages: Key distribution is difficult (how to securely share the key?). Number of keys required grows exponentially as $N(N-1)/2$ for $N$ users.
  • Common Algorithms: AES (Advanced Encryption Standard), DES, 3DES, Blowfish.
  Symmetric Cryptography:
  [Plaintext] ───(Encrypt with Secret Key)───→ [Ciphertext] ───(Decrypt with Same Secret Key)───→ [Plaintext]

Asymmetric Key Cryptography (Public Key)

Uses a **pair of keys**: a Public Key (shared openly with everyone) and a Private Key (kept secret by the owner).

  • Data encrypted with a user's Public Key can only be decrypted with that specific user's Private Key.
  • Data encrypted with a user's Private Key can only be decrypted with that user's Public Key (used for Digital Signatures).
  • Advantages: Solves the key distribution problem. Only $2N$ keys are required for $N$ users.
  • Disadvantages: Computationally slow and heavy. Used mainly to encrypt small symmetric session keys.
  • Common Algorithms: RSA, Diffie-Hellman (key exchange), ECC (Elliptic Curve Cryptography).
  Asymmetric Cryptography:
  [Plaintext] ───(Encrypt with Bob's Public Key)───→ [Ciphertext] ───(Decrypt with Bob's Private Key)───→ [Plaintext]

8.4 Network Protection: VPNs, Firewalls, and Proxies

Virtual Private Network (VPN)

A VPN creates a secure, encrypted tunnel over public networks (like the Internet), allowing remote users or branches to securely connect to a private organization network. It relies on protocols like **IPsec** or **SSL/TLS**. 

  Remote PC ───[ Encrypted VPN Tunnel (Internet) ]─── Firewall ─── Corporate LAN

Firewalls

A security device that monitors and filters incoming and outgoing network traffic based on an organization's previously established security rules.

  • Packet Filtering Firewalls: Operates at Layers 3 and 4. Examines packets in isolation, filtering based on source/destination IP addresses, port numbers, and protocol types (e.g., Access Control Lists - ACLs).
  • Stateful Inspection Firewalls: Tracks active TCP connection states. It permits incoming traffic only if it is part of an established outbound connection session.
  • Application Proxy Firewalls: Operates at Layer 7. Acts as an intermediary, inspecting the actual application data (e.g., blocking SQL injection attacks inside HTTP payloads).

Proxy Servers

A proxy server acts as a gateway between users and the internet:

  • Forward Proxy: Sits in front of clients. It intercepts outbound client requests, hides client IPs, filters content (blocking inappropriate sites in schools), and caches web pages to save bandwidth.
  • Reverse Proxy: Sits in front of servers. It intercepts inbound requests, provides load balancing, SSL termination, caching, and protects servers from direct exposure.

8.5 RSA Public Key Cryptography Algorithm (Worked Example)

The **RSA algorithm** is named after Ron Rivest, Adi Shamir, and Leonard Adleman. It is based on the mathematical difficulty of factoring large prime numbers.

RSA Algorithm Numerical Walkthrough

Problem: Generate an RSA key pair using prime numbers $p = 3$ and $q = 11$. Encrypt the message value $M = 7$, and decrypt the resulting ciphertext to verify.

Solution:
Step 1: Compute $n$ and $z$ (Euler's totient $\phi(n)$):
$n = p \times q = 3 \times 11 = 33$.
$z = \phi(n) = (p - 1) \times (q - 1) = 2 \times 10 = 20$.

Step 2: Choose public exponent $e$:
$e$ must be co-prime to $z$ (i.e., $gcd(e, z) = 1$) and $1 < e < z$.
Let's choose $e = 3$ (since $gcd(3, 20) = 1$).

Step 3: Calculate private exponent $d$:
$d$ must satisfy: $(d \times e) \bmod z = 1 \implies (d \times 3) \bmod 20 = 1$.
Test values of $d$:
If $d=7 \implies 7 \times 3 = 21 \equiv 1 \bmod 20$. So $d = 7$.

Key Pairs:
- Public Key: $(e, n) = (3, 33)$.
- Private Key: $(d, n) = (7, 33)$.

Step 4: Encryption:
Ciphertext $C = M^e \bmod n$
$C = 7^3 \bmod 33 = 343 \bmod 33$.
Since $33 \times 10 = 330$, $343 - 330 = 13 \implies C = 13$.

Step 5: Decryption:
Decrypted Plaintext $P = C^d \bmod n$
$P = 13^7 \bmod 33$.
Compute $13^7 \bmod 33$ using exponentiation properties:
$13^1 \bmod 33 = 13$
$13^2 \bmod 33 = 169 \bmod 33 = 4$ (since $33 \times 5 = 165$)
$13^4 \bmod 33 = (13^2)^2 \bmod 33 = 4^2 = 16$
$13^7 = 13^4 \times 13^2 \times 13^1 \implies 16 \times 4 \times 13 = 64 \times 13$.
$64 \bmod 33 = 31 \equiv -2 \bmod 33$.
$P = (-2 \times 13) \bmod 33 = -26 \equiv 7 \bmod 33$.
So $P = 7$, which matches the original message $M$.

8.6 IPsec (IP Security) Protocol Architecture

IPsec secures layer 3 (Network Layer) packets. It comprises two main sub-protocols:

  • Authentication Header (AH): Provides source authentication and data integrity, but **does not encrypt** the data payload. Protects against spoofing.
  • Encapsulating Security Payload (ESP): Provides source authentication, data integrity, and **data encryption** for confidentiality.

IPsec Operation Modes

IPsec Mode Header Modification Payload Protected Best For
Transport Mode Inserts IPsec header between IP header and TCP/UDP header Upper-layer payload only (original IP header remains unencrypted) End-to-end host communication (client to server)
Tunnel Mode Encapsulates the entire original IP packet inside a new IP packet with a new header Entire original packet (IP header + data payload) is encrypted Site-to-site VPNs (gateway-to-gateway)

8.7 Information Security Fundamentals and DMZ Design

The CIA Triad

The core objectives of information security are represented by the CIA Triad:

  • Confidentiality: Ensuring that information is accessible only to authorized users. Achieved using encryption.
  • Integrity: Ensuring that data is not altered or corrupted during transmission. Achieved using hash algorithms (MD5, SHA-256) and checksums.
  • Availability: Ensuring that authorized users have access to systems and information when needed. Achieved using backups, redundancy, and DDoS mitigation.

DMZ (Demilitarized Zone) Architecture

A **DMZ** is a physical or logical sub-network that exposes an organization's external-facing services (like Web, Mail, DNS servers) to the untrusted public Internet, while keeping the rest of the internal network (database, active directory) isolated: 

  Internet (Untrusted)
         │
         ▼  [External Firewall]
  ┌──────────────┐
  │  DMZ Subnet  │ ─── Exposes Web/Mail Server (Publicly accessible)
  └──────┬───────┘
         │
         ▼  [Internal Firewall]
  Private LAN (Trusted) ─── Contains Database, Employee PCs (Completely isolated)

8.9 Wireless Network Security Protocols

Wireless signals travel in open space, making them highly vulnerable to sniffing and unauthorized access. Several security standards have evolved:

  • WEP (Wired Equivalent Privacy): The original 802.11 security standard. It uses the RC4 stream cipher with a short, static key.
    Extremely vulnerable. Can be cracked in minutes using simple tools.
  • WPA (Wi-Fi Protected Access): Created as a temporary replacement for WEP. Uses TKIP (Temporal Key Integrity Protocol) to dynamically change keys.
  • WPA2: Uses the robust **AES (Advanced Encryption Standard)** cipher instead of TKIP, providing excellent security. The standard for home/enterprise Wi-Fi for many years. Uses a 4-way handshake (vulnerable to dictionary attacks if pre-shared key is weak).
  • WPA3: The latest standard. Replaces pre-shared keys with **SAE (Simultaneous Authentication of Equals)** handshake, protecting against offline dictionary attacks and providing forward secrecy.

8.10 Security Services and Cryptographic Hashing

Essential Security Services

  • Authentication: Verification of the identity of communicating entities.
  • Access Control: Limiting access to authorized resources based on user permissions.
  • Confidentiality: Protecting data from disclosure to unauthorized entities.
  • Data Integrity: Ensuring received data has not been modified.
  • Non-repudiation: Preventing an entity from denying a previous action or transaction. For example, a digital signature on a contract prevents the sender from claiming they did not sign it.

Cryptographic Hash Functions

A hash function takes an arbitrary-sized input and produces a fixed-size output (digest) that is unique to that input. Key characteristics:

  • One-way function: It is computationally impossible to reconstruct the input from the hash value.
  • Collision resistance: It is highly unlikely that two different inputs will produce the same hash value.
  • Common Algorithms: MD5 (128-bit digest, considered weak), SHA-1 (160-bit digest, weak), SHA-256 (256-bit digest, very strong).

8.11 Digital Signatures

A digital signature is a mathematical scheme used to demonstrate the authenticity of a digital message or document. It provides three main security services: **Authentication**, **Data Integrity**, and **Non-repudiation**.

Digital Signature Flow

  Sender (Signing):
  [Message] ───► (Hash Function) ───► [Message Digest] ───(Encrypt with Private Key)───► [Digital Signature]

  Receiver (Verification):
  [Signature] ───(Decrypt with Sender's Public Key)───► [Received Digest]
                                                                │  Compare
  [Received Msg] ───► (Hash Function) ───────────────► [Calculated Digest] ◄┘ (Must Match)
  1. Signing Process:
    • The sender passes the message through a cryptographic hash function to create a unique *Message Digest*.
    • The sender encrypts this digest using their own **Private Key**. The result is the *Digital Signature*.
    • The message and the signature are sent to the receiver.
  2. Verification Process:
    • The receiver decrypts the signature using the sender's **Public Key** to recover the original *Message Digest*.
    • The receiver hashes the received message using the same hash function to calculate a new *Message Digest*.
    • If the calculated digest matches the decrypted digest, the message is authentic and unaltered.

8.12 AAA Framework and Malware Taxonomy

The AAA Security Model

AAA is an architectural framework for configuring enterprise network access control:

  • Authentication: "Who are you?" Verifies credentials (username/password, tokens, biometrics).
  • Authorization: "What are you allowed to do?" Determines user access rights and privileges.
  • Accounting: "What did you do?" Tracks user activities, session durations, and resources consumed (used for auditing and billing).
  • Protocols: Common AAA protocols are **RADIUS** (open standard, UDP-based, encrypts only passwords) and **TACACS+** (Cisco proprietary, TCP-based, encrypts the entire packet payload).

Malware Taxonomy

Malware is any software intentionally designed to cause damage to a computer, server, client, or network:

  • Virus: Malicious code that attaches itself to clean host files and replicates when the program is executed. Requires human action to spread.
  • Worm: Standalone malicious software that replicates and spreads automatically across network links without requiring host files or human intervention. Explores network vulnerabilities.
  • Trojan Horse: Software disguised as legitimate, useful programs (e.g., utility software) but containing hidden malicious functions (backdoors).
  • Ransomware: Encrypts user files and demands payment (ransom) to provide decryption keys.
  • Spyware: Secretly monitors user behavior, keystrokes (keyloggers), and personal data, sending information back to attackers.
