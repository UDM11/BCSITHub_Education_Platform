Unit 9: Pipelining [4 Hours] - Detailed Study Guide

9.1 Pipelining Performance and Flynn's Classification

Pipelining is a technique of decomposing a sequential process into sub-operations, with each sub-operation being executed in a dedicated segment that operates concurrently with all other segments. It allows multiple instructions to overlap in execution, increasing instruction throughput.

Pipelining Performance Formulas:

Consider a k-segment pipeline with clock cycle time tp. To execute n tasks:

  • Time in Pipeline (Tp): Tp = (k + n - 1) * tp
  • Time in Non-Pipeline (Tn): Tn = n * tn (where tn is the time to execute a single task sequentially).
  • Speedup Ratio (S): S = Tn / Tp = (n * tn) / ((k + n - 1) * tp)
  • As n becomes very large (approaches infinity), the Speedup approaches the theoretical maximum: S_max = tn / tp. If tn = k * tp, then maximum speedup is exactly k (the number of pipeline segments).

Flynn's Classification of Computer Systems:

Flynn's taxonomy classifies computers into four categories based on the number of concurrent instruction streams and data streams:

Category Description Hardware Structure Examples
SISD Single Instruction Stream, Single Data Stream Single CU, Single ALU. Serial execution. Traditional uniprocessor systems (Intel 8085).
SIMD Single Instruction Stream, Multiple Data Stream Single CU, Multiple ALUs. Same instruction processes different data. Vector/Array Processors, GPUs (Graphics Processing Units).
MISD Multiple Instruction Stream, Single Data Stream Multiple CUs, Single ALU. Multiple instructions process same data. Rarely implemented (mainly used for fault-tolerant systems).
MIMD Multiple Instruction Stream, Multiple Data Stream Multiple CUs, Multiple ALUs. Independent parallel execution. Multi-core CPUs, distributed clusters, supercomputers.

9.2 Arithmetic Pipeline

Arithmetic pipelines decompose arithmetic operations (like floating-point addition/multiplication) into sub-operations that can be pipelined.

Floating-Point Addition and Subtraction Pipeline:

Floating-point operations are performed on numbers of the form X = A * 2^a and Y = B * 2^b. The operation consists of 4 segments:

[Input X, Y] ---> [ Segment 1: Compare Exponents ] | v [ Segment 2: Align Mantissas ] | v [ Segment 3: Add/Subtract Mantissas ] | v [ Segment 4: Normalize Result ] ---> [Output]

Detailed Arithmetic Pipeline Step Example:

Let's add X = 0.95 * 10^3 and Y = 0.82 * 10^2:

  • Segment 1 (Compare Exponents): The exponents are 3 and 2. The difference is 3 - 2 = 1.
  • Segment 2 (Align Mantissas): Shift the mantissa of Y right by 1 position to match exponents. Y becomes 0.082 * 10^3.
  • Segment 3 (Add Mantissas): Add the aligned mantissas: 0.95 + 0.082 = 1.032. Temporary result: 1.032 * 10^3.
  • Segment 4 (Normalize Result): Shift the mantissa right by 1 position and increment the exponent to maintain standard form. Final result: 0.1032 * 10^4.

9.3 Instruction Pipeline

An Instruction Pipeline executes stream instructions by overlapping the fetch, decode, and execute phases of different instructions. A typical 4-Segment Instruction Pipeline consists of:

  1. FI (Fetch Instruction): Fetches the next instruction from memory.
  2. DA (Decode Instruction and calculate effective address): Decodes opcode and evaluates the operand address.
  3. FO (Fetch Operand): Fetches the operand from RAM.
  4. EX (Execute): Performs the operation and writes back results.

9.4 Pipeline Hazards and Mitigation

Pipeline hazards are situations that prevent the next instruction in the instruction stream from executing in its designated clock cycle. Hazards reduce pipeline efficiency.

1. Structural Hazards (Resource Conflicts):

Occur when two instructions in the pipeline require access to the same physical resource at the same time (e.g., fetching an instruction from memory while reading data from memory).
Mitigation: Use separate Instruction Memory and Data Memory (Harvard architecture) or separate L1 cache blocks for instructions and data.

2. Data Dependency Hazards (Data Hazards):

Occur when an instruction depends on the result of a previous instruction that has not yet completed execution.
Types of Data Hazards:
- RAW (Read-After-Write): The current instruction tries to read a register before the previous instruction writes to it (most common).
- WAR (Write-After-Read): The current instruction tries to write to a register before a previous instruction reads it.
- WAW (Write-After-Write): The current instruction tries to write to a register before a previous instruction writes to it.
Mitigation:
- Operand Forwarding (Bypassing): Route intermediate ALU results directly to the ALU inputs of the next cycle, bypassing register writes.
- Register Renaming: Use physical registers to eliminate false dependencies.
- Software Delay Slots: Compiler inserts independent instructions or NOP bubbles between dependent operations.

3. Control Hazards (Branch Hazards):

Occur when a branch/jump instruction changes the Program Counter (PC). The pipeline does not know the next instruction address until the branch is evaluated, causing flushed cycles.
Mitigation:
- Branch Prediction: Guess the branch outcome. Static prediction always guesses "taken" or "not taken." Dynamic prediction uses a Branch Target Buffer (BTB) to predict based on execution history.
- Delay Slot Branching: The compiler inserts independent instructions right after the branch that execute regardless of the branch outcome, avoiding wasted cycles.
