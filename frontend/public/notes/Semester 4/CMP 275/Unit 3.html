3.1 Computer Architecture vs. Computer Organization

Computer Architecture refers to those attributes of a system visible to a programmer, or, put another way, those attributes that have a direct impact on the logical execution of a program. Examples of architectural attributes include the instruction set, the number of bits used to represent data types, input/output mechanisms, and techniques for addressing memory.

Computer Organization refers to the operational units and their interconnections that realize the architectural specifications. Organizational attributes include hardware details transparent to the programmer, such as control signals, interfaces between the computer and peripherals, and the memory technology used (e.g., SRAM vs. DRAM).

Example: It is an architectural design decision whether a computer will have a multiply instruction. It is an organizational decision whether that instruction will be implemented by a dedicated multiply hardware unit or by iterative addition logic in the ALU.

3.2 Register Organization of a Basic Computer

The internal registers of the basic computer are organized to facilitate data transfer, memory address tracking, and instruction processing. Below is a comprehensive list of these registers:

Register Symbol Name Size (Bits) Function
DR Data Register 16 Holds memory operand values read from memory.
AR Address Register 12 Holds address for memory access. Connected to address lines.
AC Accumulator 16 General-purpose processor register for ALU operations.
IR Instruction Register 16 Holds the instruction code currently being executed.
PC Program Counter 12 Holds address of the next instruction to be fetched from memory.
TR Temporary Register 16 Holds temporary data during processing operations.
INPR Input Register 8 Holds 8-bit input character from device.
OUTR Output Register 8 Holds 8-bit output character for display device.

3.3 Common Bus System Architecture

Connecting all registers with individual wires would require a highly complex network of lines. To simplify this, a Common Bus System is used. It allows the output of only one register to be placed on the bus at a time, while multiple registers can read from it.

1. Multiplexer-Based Bus System:

Constructed using 16-to-1 multiplexers (or 8-to-1 depending on register counts). Each register output is connected to a specific multiplexer input line. Three selection lines (S2, S1, S0) select which register's data is placed on the bus.

2. Three-State Buffer Bus System:

Constructed using Three-state buffers (like 74LS244). A three-state gate has three states: 0, 1, and high-impedance (Hi-Z). In Hi-Z state, the output is electrically isolated from the bus. A decoder uses the select lines to enable the three-state buffer of only one register, placing its bits on the shared bus lines.

3.4 Instruction Formats and Addressing Modes

An Instruction Format specifies the structure of bits in a machine instruction. A basic computer instruction format consists of three fields:

Instruction Word Bit Layout: +-----+----------+------------------------------------------+ | I | Opcode | Address | +-----+----------+------------------------------------------+ 15 14 12 11 0 Where: - I (Bit 15) : Addressing Mode. 0 = Direct Addressing, 1 = Indirect Addressing. - Opcode : 3 bits (bits 14-12) specifying operations (000 to 111). - Address : 12 bits (bits 11-0) specifying memory address.

Instruction Formats by Address Fields:

Let's evaluate how the algebraic expression X = (A + B) * (C + D) is executed in different instruction set architectures:

1. Three-Address Instructions:

Each instruction specifies two source operands and one destination operand.


ADD R1, A, B     ; R1 <- M[A] + M[B]
ADD R2, C, D     ; R2 <- M[C] + M[D]
MUL X, R1, R2     ; M[X] <- R1 * R2

2. Two-Address Instructions:

The destination operand doubles as one of the source operands.


MOV R1, A        ; R1 <- M[A]
ADD R1, B        ; R1 <- R1 + M[B]
MOV R2, C        ; R2 <- M[C]
ADD R2, D        ; R2 <- R2 + M[D]
MUL R1, R2       ; R1 <- R1 * R2
MOV X, R1        ; M[X] <- R1

3. One-Address Instructions (Accumulator-Based):

Uses an implicit Accumulator (AC) register for all operations.


LOAD A           ; AC <- M[A]
ADD B            ; AC <- AC + M[B]
STORE T          ; M[T] <- AC (store intermediate sum)
LOAD C           ; AC <- M[C]
ADD D            ; AC <- AC + M[D]
MUL T            ; AC <- AC * M[T]
STORE X          ; M[X] <- AC

4. Zero-Address Instructions (Stack-Based):

Operands are popped from the top of the stack, processed, and the result is pushed back.


PUSH A           ; Stack <- M[A]
PUSH B           ; Stack <- M[B]
ADD              ; Pop two, add, push sum
PUSH C           ; Stack <- M[C]
PUSH D           ; Stack <- M[D]
ADD              ; Pop two, add, push sum
MUL              ; Pop two, multiply, push product
POP X            ; M[X] <- Pop top of stack

3.5 Stack Organization

A stack is a storage device that stores information in such a manner that the item stored last is the first to be retrieved (Last-In, First-Out: LIFO). It is controlled by the Stack Pointer (SP).

1. Register Stack Organization:

Implemented as a dedicated array of high-speed registers. A 64-word stack requires a 6-bit Stack Pointer (since 2^6 = 64). It uses flag flip-flops FULL and EMPTY to detect stack limits.

Register Stack Push Micro-operations:


SP <- SP + 1      ; Increment Stack Pointer
DR <- Data        ; Get data
M[SP] <- DR       ; Write to stack memory
If (SP = 0) then (FULL <- 1) ; If pointer wraps to 0, stack is full
EMPTY <- 0        ; Stack is no longer empty

Register Stack Pop Micro-operations:


DR <- M[SP]       ; Read data from top of stack
SP <- SP - 1      ; Decrement Stack Pointer
If (SP = 0) then (EMPTY <- 1) ; If pointer wraps to 0, stack is empty
FULL <- 0         ; Stack is no longer full

2. Memory Stack Organization:

Implemented in a dedicated segment of main memory (RAM). The stack grows downward in memory, meaning PUSH operations decrement the SP, and POP operations increment the SP.

Memory Stack Push:


SP <- SP - 1      ; Decrement pointer (moves to lower memory address)
M[SP] <- DR       ; Write data to memory address in SP

Memory Stack Pop:


DR <- M[SP]       ; Read data from memory address in SP
SP <- SP + 1      ; Increment pointer (moves to higher memory address)
