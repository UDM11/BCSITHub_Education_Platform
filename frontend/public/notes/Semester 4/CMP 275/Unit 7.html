7.1 I/O Interfaces, Addressing, and Command Types

An I/O Interface is a hardware circuit that coordinates the flow of information between the internal CPU registers and external peripheral devices. It converts signal levels, handles speed differences, and provides status flags (such as busy or ready).

Typical I/O Interface Block Diagram:

+------------------------------------+ | System Buses | ====== Data =====|======== [ Data Bus Buffer ] =======|<=======> CPU ====== Addr =====|======== [ Address Decoder ] =======|========> CPU ====== Ctrl =====|======== [ Control Logic ] =======|<=======> CPU +-----------------+------------------+ | +------------+------------+ | | v v +---------+---------+ +---------+---------+ | Status/Control | | Data Input/ | | Registers | | Output Register | +---------+---------+ +---------+---------+ | | +------------+------------+ | v [ Peripheral Device ]

Types of I/O Commands:

  • Control Command: Sent to activate a peripheral and instruct it on what action to perform (e.g., rewinding a tape, setting baud rates).
  • Status Command: Reads the status register of the interface to check flag conditions (e.g., checking if the printer is out of paper, or if data is ready).
  • Data Output Command: Instructs the interface to accept a data byte from the bus and send it to the peripheral.
  • Data Input Command: Instructs the interface to read a byte from the peripheral and place it on the system data bus.

Comparison: Isolated vs. Memory-Mapped I/O

Feature Isolated I/O (I/O Mapped I/O) Memory-Mapped I/O
Address Space Uses a separate 8-bit or 16-bit port address space. I/O devices are assigned addresses in the memory space.
Memory Space Loss No memory space is lost. Reduces available memory space for programs.
Instructions Limited to special instructions (e.g., IN, OUT). Any memory instruction can be used (e.g., MOV, LDA, STA).
Control Signals Distinct control signals (IOR', IOW'). Standard memory control signals (MEMR', MEMW').
Execution Speed Faster execution of dedicated instructions. Slightly slower due to complex address decoding.

7.2 Direct Memory Access (DMA)

Direct Memory Access (DMA) is a high-speed data transfer technique where an external device (the DMA Controller) takes control of the system buses from the CPU to transfer data directly between memory and peripherals.

DMA Controller Internals:

A typical DMA controller (like Intel 8257/8237) contains:

  • Address Register: Holds the starting memory address for the transfer. It increments automatically after each byte is moved.
  • Word Count Register: Holds the number of bytes to transfer. It decrements after each byte, triggering a terminal count (TC) interrupt when it reaches 0.
  • Control/Status Register: Enables channels, sets priorities, and monitors transfer states.

DMA Handshake Sequence:

Peripheral DMA Controller CPU | | | |--- DMA Request (DREQ) --------->| | | |--- Hold Request (HOLD) ----->| | | | | |<-- Hold Acknowledge (HLDA) --| |<-- DMA Acknowledge (DACK) ------| | | | | [======= Bi-directional high-speed data transfer directly RAM <-> I/O =======]

Modes of DMA Transfers:

  • Burst Transfer Mode: The DMA controller maintains control of the system buses until the entire block of data is transferred. This is the fastest method but blocks the CPU from executing instructions.
  • Cycle Stealing Mode: The DMA controller requests the buses, transfers a single byte, and returns control to the CPU. It "steals" one clock cycle at a time, allowing the CPU to run concurrently.
  • Transparent Mode: The DMA controller only transfers data when the CPU is executing internal operations and not accessing the system buses. This does not impact CPU performance but has the lowest transfer rate.

7.3 Input-Output Processor (IOP)

An IOP is a dedicated coprocessor with its own instruction set designed to handle all peripheral communication independently of the main CPU. The CPU only initiates operations by sending an instruction to the IOP. The IOP then handles the transfer in the background, signaling the CPU via an interrupt only when the entire task is complete.

7.4 Data Communication Protocols

Data transmission between computers uses structured protocols to frame packets and verify integrity.

1. Character-Oriented Protocols (e.g., IBM BISYNC):

Data is transmitted as a sequence of characters (bytes). Control characters define packet boundaries:
[SYN] [SYN] [SOH] [Header] [STX] [Text Payload] [ETX] [BCC]
If a control character (like ETX) appears in the text payload, the transmitter inserts a DLE (Data Link Escape) character before it. The receiver detects the DLE and treats the following ETX as raw data rather than the end of the packet (Byte Stuffing).

2. Bit-Oriented Protocols (e.g., HDLC):

Data is transmitted as a continuous stream of bits. Frame boundaries are marked by a unique flag bit pattern: 01111110 (Hex 7E).
Bit Stuffing Rule: To prevent this flag pattern from appearing within the payload, the transmitter monitors the bit stream. If five consecutive 1s are sent, the transmitter automatically inserts a 0 bit. The receiver detects this: if it sees five 1s followed by a 0, it removes the 0 bit. If it sees five 1s followed by a 1, it identifies it as a flag or abort signal.

Bit Stuffing Example:


Original Payload:  1101 1111 1011 1111 1100
                   (Contains consecutive 1s)
                   
Transmitter Stuffing Process:
   1101 1111 [Insert 0] 1011 1111 [Insert 0] 1100
   
Transmitted Data:  1101 1111 0101 1111 0110 0
