1.1 Errors in Numerical Calculations

Numerical calculations represent approximations of continuous mathematical functions. Real numbers must be represented within the finite memory architecture of a computer, which naturally introduces discrepancies between the mathematical theoretical value and the computed output.

Accuracy vs. Precision:

  • Accuracy: Refers to how close a computed or measured value is to the true value. High accuracy means low systematic bias.
  • Precision: Refers to how closely individual calculated values agree with each other under repeated computations. High precision means low random variance.

Significant Digits:

Significant digits are those digits in a number that carry meaningful information about its precision.
Rules for determining significant digits:
1. All non-zero digits are significant (e.g., 123.45 has 5 significant digits).
2. Zeros between non-zero digits are significant (e.g., 100.02 has 5 significant digits).
3. Leading zeros are NOT significant; they serve only as placeholders (e.g., 0.00045 has 2 significant digits).
4. Trailing zeros after a decimal point are significant (e.g., 45.00 has 4 significant digits).

Sources of Numerical Errors:

  1. Inherent Errors (Input Errors): These arise from physical constraints of measurements or limits of data gathering systems. For instance, measuring a temperature to the nearest tenth of a degree carries an inherent error of ±0.05 degrees.
  2. Round-Off Errors: These occur because computers use binary floating-point representation (such as the IEEE 754 standard) to represent real numbers. Representing numbers like 1/3 or π requires rounding off trailing infinite decimal/binary places.
    Chopping: Truncating all digits past the allowed word length. (e.g., 0.56789 chopped to 3 digits is 0.567).
    Symmetric Rounding: Rounding to the nearest value. (e.g., 0.56789 rounded to 3 digits is 0.568).
  3. Truncation Errors: These occur when an infinite mathematical process is terminated after a finite number of terms. For example, approximating the infinite sum representing sin(x) using a finite polynomial introduces truncation error.

Mathematical Formulas for Error Metrics:

Let X be the true value and X_a be the approximated value.

  • Absolute Error (E_a):
    E_a = |X - X_a|
  • Relative Error (E_r):
    E_r = |X - X_a| / |X| = E_a / |X| (provided X != 0)
  • Percentage Error (E_p):
    E_p = E_r * 100%

Detailed Solved Mathematical Example:

Question: Let X = 2/3 and its approximate value be X_a = 0.667. Compute the absolute, relative, and percentage errors. State the number of significant digits in X_a.


True Value (X) = 2/3 = 0.666666666666...
Approximate Value (X_a) = 0.667

1. Absolute Error (E_a):
   E_a = |X - X_a| 
       = |0.666666... - 0.667000|
       = 0.000333333... = 1/3000

2. Relative Error (E_r):
   E_r = E_a / |X|
       = (1/3000) / (2/3)
       = (1/3000) * (3/2) = 3/6000 = 1/2000 = 0.0005

3. Percentage Error (E_p):
   E_p = E_r * 100%
       = 0.0005 * 100% = 0.05%

4. Significant Digits check:
   X_a = 0.667 has 3 significant digits (leading zero is placeholder).

1.2 Computer Floating-Point Representation (IEEE 754 Standard)

Computers represent real numbers using the **IEEE 754 Standard**. Numbers are stored in a normalized scientific notation binary format: ±1.mantissa * 2^exponent.

1. Single Precision (32-bit):

  • Sign bit (S): 1 bit (0 for positive, 1 for negative).
  • Exponent (E): 8 bits. Biased by 127. True Exponent e = E - 127.
  • Mantissa/Fraction (M): 23 bits. The leading 1 before the decimal point is implicit (not stored).

2. Double Precision (64-bit):

  • Sign bit (S): 1 bit.
  • Exponent (E): 11 bits. Biased by 1023. True Exponent e = E - 1023.
  • Mantissa/Fraction (M): 52 bits.

Detailed Step-by-Step Conversion Example:

Question: Convert the decimal number -12.625 into IEEE 754 Single Precision 32-bit binary format.


Step 1: Convert decimal magnitude to binary:
  - Integer part: 12 = 1100 (binary)
  - Fractional part: 0.625
    0.625 * 2 = 1.250 -> 1
    0.250 * 2 = 0.500 -> 0
    0.500 * 2 = 1.000 -> 1
    0.625 (decimal) = 0.101 (binary)
  - Combined magnitude: 1100.101 (binary)

Step 2: Normalize the binary number:
  Shift the decimal point left 3 positions so there is exactly one non-zero leading digit:
  1100.101 = 1.100101 * 2^3
  - True Exponent (e) = 3
  - Normalized Mantissa (excluding leading 1) = 100101

Step 3: Calculate Biased Exponent (E):
  E = e + Bias = 3 + 127 = 130
  Convert 130 to 8-bit binary:
  130 / 2 = 65 remainder 0
  65 / 2 = 32 remainder 1
  32 / 2 = 16 remainder 0
  16 / 2 = 8 remainder 0
  8 / 2 = 4 remainder 0
  4 / 2 = 2 remainder 0
  2 / 2 = 1 remainder 0
  1 / 2 = 0 remainder 1
  E = 10000010 (binary)

Step 4: Layout final 32 bits:
  - Sign (S): 1 (Negative number)
  - Exponent (E): 10000010
  - Mantissa (M, padded to 23 bits): 10010100000000000000000
  
  Final Binary String:
  1 10000010 10010100000000000000000
  
  Hexadecimal representation:
  1100 0001 0100 1010 0000 0000 0000 0000 = C14A0000H

C Program to inspect Float Binary Layout:


#include <stdio.h>

// Union to map float and int to same memory space
union FloatParts {
    float f;
    struct {
        unsigned int mantissa : 23;
        unsigned int exponent : 8;
        unsigned int sign : 1;
    } parts;
};

int main() {
    union FloatParts num;
    num.f = -12.625;
    
    printf("Inspecting float representation of %f:\n", num.f);
    printf("Sign Bit: %d\n", num.parts.sign);
    printf("Biased Exponent (Decimal): %d\n", num.parts.exponent);
    printf("Mantissa bits (Hex): 0x%X\n", num.parts.mantissa);
    
    // Print binary representation
    printf("Binary layout: %d ", num.parts.sign);
    for (int i = 7; i >= 0; i--) {
        printf("%d", (num.parts.exponent >> i) & 1);
    }
    printf(" ");
    for (int i = 22; i >= 0; i--) {
        printf("%d", (num.parts.mantissa >> i) & 1);
    }
    printf("\n");
    return 0;
}

1.3 Computer Software Environments (C vs. MATLAB/Octave)

Solving numerical problems requires choosing an appropriate programming model. Below is a detailed analysis of the two primary software methodologies:

Compiled Language: C programming

  • Design Philosophy: High performance, manual memory allocation, compiled down to native machine codes.
  • Advantages: Executed extremely fast. Best for production systems and resource-constrained microcontrollers.
  • Disadvantages: Lacks built-in support for vector and matrix operations. Plotting graphs requires complex third-party GUI or OpenGL libraries.

Interpreted Environment: MATLAB / GNU Octave

  • Design Philosophy: High-level, interactive matrix laboratory. All data structures are inherently treated as matrices.
  • Advantages: Native support for linear algebra, easy plotting commands, rapid prototyping.
  • Disadvantages: Interpreted execution is slower than compiled C code. Requires higher runtime memory.

Comparative Implementation Example (Calculating Vector Dot Product):

Let's compare the code required to calculate the dot product of two vectors A and B:

C Language Implementation:


#include <stdio.h>

int main() {
    double A[] = {1.0, 2.0, 3.0};
    double B[] = {4.0, 5.0, 6.0};
    int n = sizeof(A) / sizeof(A[0]);
    double dot_product = 0.0;
    
    for (int i = 0; i < n; i++) {
        dot_product += A[i] * B[i];
    }
    
    printf("Dot Product in C: %lf\n", dot_product);
    return 0;
}

MATLAB / GNU Octave Implementation:


A = [1.0, 2.0, 3.0];
B = [4.0, 5.0, 6.0];
dot_product = dot(A, B);
disp(['Dot Product in MATLAB: ', num2str(dot_product)]);

1.4 Mathematical Preliminaries: Taylor Series and Expansions

The Taylor Series Expansion is a fundamental mathematical tool in numerical analysis. It allows us to approximate any infinitely differentiable function near a point using a polynomial.

Taylor Series Theorem:

If a function f(x) is continuous and has derivatives of all orders on an interval containing a, the Taylor series expansion of f(x) centered at x = a is given by:


f(x) = f(a) + f'(a)*(x-a)/1! + f''(a)*(x-a)^2/2! + f'''(a)*(x-a)^3/3! + ... + f^(n)(a)*(x-a)^n/n! + R_n(x)

Where:
- R_n(x) is the Lagrange Remainder Term representing the truncation error:
  R_n(x) = [ f^(n+1)(c) * (x - a)^(n+1) ] / (n+1)!
  for some value c lying strictly between a and x.

Maclaurin Series (Taylor Series centered at a = 0):

Setting a = 0 simplifies the formula:


f(x) = f(0) + f'(0)*x/1! + f''(0)*x^2/2! + f'''(0)*x^3/3! + ... + f^(n)(0)*x^n/n! + R_n(x)

Complete Derivation of Maclaurin Expansions:

1. Exponential Function f(x) = e^x

Let's calculate the derivatives of f(x) = e^x and evaluate them at x = 0:


f(x) = e^x        =>  f(0) = e^0 = 1
f'(x) = e^x       =>  f'(0) = 1
f''(x) = e^x      =>  f''(0) = 1
f'''(x) = e^x     =>  f'''(0) = 1
...
f^(n)(x) = e^x    =>  f^(n)(0) = 1

Substituting these values into the Maclaurin series formula yields:
e^x = 1 + x + x^2/2! + x^3/3! + x^4/4! + ... + x^n/n!

2. Sine Function f(x) = sin(x)

Let's calculate the derivatives of f(x) = sin(x) and evaluate them at x = 0:


f(x) = sin(x)     =>  f(0) = sin(0) = 0
f'(x) = cos(x)    =>  f'(0) = cos(0) = 1
f''(x) = -sin(x)  =>  f''(0) = 0
f'''(x) = -cos(x) =>  f'''(0) = -1
f^(4)(x) = sin(x) =>  f^(4)(0) = 0

Substituting these values yields only odd power terms with alternating signs:
sin(x) = x - x^3/3! + x^5/5! - x^7/7! + ...

3. Cosine Function f(x) = cos(x)

Let's calculate the derivatives of f(x) = cos(x) and evaluate them at x = 0:


f(x) = cos(x)     =>  f(0) = cos(0) = 1
f'(x) = -sin(x)   =>  f'(0) = 0
f''(x) = -cos(x)  =>  f''(0) = -1
f'''(x) = sin(x)  =>  f'''(0) = 0
f^(4)(x) = cos(x) =>  f^(4)(0) = 1

Substituting these values yields only even power terms with alternating signs:
cos(x) = 1 - x^2/2! + x^4/4! - x^6/6! + ...

Complete C Code to Calculate Expansions and Track Truncation Errors:

The following C program calculates e^x using its Taylor series expansion up to N terms, compares the result with the built-in math function value, and displays the truncation error:


#include <stdio.h>
#include <math.h>

// Function to calculate factorial
double factorial(int n) {
    double fact = 1.0;
    for (int i = 1; i <= n; i++) {
        fact *= i;
    }
    return fact;
}

// Function to approximate e^x
double approximate_exp(double x, int terms) {
    double sum = 0.0;
    for (int i = 0; i < terms; i++) {
        sum += pow(x, i) / factorial(i);
    }
    return sum;
}

int main() {
    double x = 1.2;
    printf("Evaluating e^%lf:\n\n", x);
    printf("%-10s %-20s %-20s %-20s\n", "Terms", "Approx Value", "True Value", "Abs Error");
    
    double true_val = exp(x);
    for (int t = 1; t <= 10; t++) {
        double approx = approximate_exp(x, t);
        double abs_err = fabs(true_val - approx);
        printf("%-10d %-20.10f %-20.10f %-20.10e\n", t, approx, true_val, abs_err);
    }
    return 0;
}
