7.1 Introduction to Database

A database is an organized collection of structured data, typically stored and accessed electronically from a computer system. Databases are designed to manage large volumes of data efficiently, supporting multiple users and applications simultaneously while ensuring data integrity and security.

📊 Purpose
To store, manage, and retrieve data efficiently. Databases enable data sharing, reduce redundancy, and maintain data consistency across applications.
🧩 Components
Data (stored in tables), metadata (data about data), and a Database Management System (DBMS) that provides the interface for managing the data.
  • Characteristics: Persistent storage, structured organization, support for multiple views, concurrent access, and transaction management.
  • Types: Relational (SQL), NoSQL (document, key-value, graph), and cloud databases.
  • Examples: MySQL, Oracle Database, Microsoft SQL Server, PostgreSQL, MongoDB, and cloud services like Amazon RDS and Google Cloud Spanner.
💡 Core idea: A database is more than just data — it's a structured system that enables efficient storage, retrieval, and manipulation of information.

7.2 Data Concepts and Characteristics

Understanding data concepts and the characteristics that define quality data is essential for effective database design and management.

Data Concepts

  • Data: Raw, unprocessed facts and figures (e.g., "John Doe", "28", "New York").
  • Information: Data that has been processed, organized, and given context to make it meaningful (e.g., "John Doe is 28 years old and lives in New York").
  • Metadata: Data about data — describes the structure, constraints, and characteristics of data (e.g., column names, data types, relationships).
  • Database Schema: The logical blueprint of a database, defining tables, columns, data types, and relationships.

Characteristics of Quality Data

  • Accuracy: Data must be correct and error-free. Inaccurate data leads to poor decisions and operational inefficiencies.
  • Consistency: Data should be uniform across the entire system. No conflicting or contradictory values should exist.
  • Completeness: Data should contain all necessary attributes without missing values.
  • Timeliness: Data should be current and updated regularly to remain relevant.
  • Security: Data must be protected from unauthorized access, breaches, and corruption.
  • Scalability: The database should be able to handle growing volumes of data without performance degradation.

7.3 Database vs. File System

Both databases and file systems store data, but they differ significantly in structure, functionality, and capabilities. Understanding these differences is crucial for choosing the right storage solution.

File System Approach

  • Structure: Data is stored in flat files (e.g., text files, spreadsheets) with no inherent relationships.
  • Data Redundancy: High redundancy — same data may be duplicated across multiple files.
  • Data Inconsistency: Changes in one file may not be reflected in others, leading to inconsistent data.
  • Access Control: Limited to file-level permissions; no fine-grained access control.
  • Querying: No standard query language; custom code is required for data retrieval and manipulation.
  • Concurrency: Limited support for multiple users accessing the same data simultaneously.
  • Examples: Storing data in CSV files, Excel spreadsheets, or text logs.

Database Approach

  • Structure: Data is stored in structured tables with relationships defined by keys.
  • Data Redundancy: Minimized through normalization techniques.
  • Data Consistency: Enforced through constraints (primary keys, foreign keys, check constraints).
  • Access Control: Granular security with user-level permissions and role-based access.
  • Querying: Standard query language (SQL) for powerful and flexible data retrieval.
  • Concurrency: Advanced transaction management ensures data integrity with multiple simultaneous users.
  • Examples: MySQL, PostgreSQL, Oracle Database.

7.4 Data Models

A data model defines how data is structured, organized, and manipulated within a database. It provides a conceptual framework for representing data and relationships.

Hierarchical Model

  • Structure: Tree-like structure with parent-child relationships. Each child has exactly one parent.
  • Advantages: Simple, fast for one-to-many relationships, easy to understand.
  • Disadvantages: Inflexible for many-to-many relationships; difficult to manage complex queries.
  • Examples: IMS (IBM Information Management System), XML data.

Network Model

  • Structure: Graph-based structure where records can have multiple parent and child relationships.
  • Advantages: More flexible than hierarchical; supports many-to-many relationships.
  • Disadvantages: Complex to design and maintain; navigation requires detailed knowledge of the structure.
  • Examples: IDMS (Integrated Database Management System), CODASYL model.

Relational Model

  • Structure: Data is organized into tables (relations) with rows (tuples) and columns (attributes). Relationships are established using keys.
  • Advantages: Simple, flexible, powerful querying with SQL, mathematical foundation (relational algebra).
  • Disadvantages: May not handle unstructured data efficiently; can have performance issues with very large datasets.
  • Examples: MySQL, PostgreSQL, Oracle, SQL Server.

NoSQL Models

  • Document Model: Stores data as JSON-like documents (MongoDB, CouchDB).
  • Key-Value Model: Stores data as key-value pairs (Redis, DynamoDB).
  • Graph Model: Stores data as nodes and edges (Neo4j, ArangoDB).
  • Advantages: Designed for scalability, flexibility, and handling unstructured data.
  • Disadvantages: Lack of standardization (no universal query language); ACID properties often sacrificed for performance.

7.5 Database Management System

A Database Management System (DBMS) is software that interacts with end-users, applications, and the database itself to capture and analyze data. It serves as the interface between users and the database, providing tools for creating, retrieving, updating, and managing data.

Key Functions of a DBMS

  • Data Definition: Creating and modifying database schemas using Data Definition Language (DDL).
  • Data Manipulation: Inserting, updating, deleting, and querying data using Data Manipulation Language (DML).
  • Data Security: Enforcing user authentication, authorization, and access controls.
  • Data Integrity: Maintaining data accuracy through constraints (primary keys, foreign keys, check constraints).
  • Concurrency Control: Managing simultaneous access by multiple users while maintaining data consistency (ACID properties).
  • Backup and Recovery: Providing mechanisms for data backup, restoration, and disaster recovery.
  • Performance Optimization: Query optimization, indexing, and caching for efficient data retrieval.

ACID Properties

  • Atomicity: Transactions are all-or-nothing — either fully completed or fully rolled back.
  • Consistency: Transactions bring the database from one valid state to another.
  • Isolation: Concurrent transactions do not interfere with each other.
  • Durability: Committed transactions persist even in case of system failure.

Popular DBMS Software

  • Relational: MySQL, PostgreSQL, Oracle, SQL Server, MariaDB.
  • NoSQL: MongoDB (document), Redis (key-value), Cassandra (wide-column), Neo4j (graph).
  • Cloud: Amazon RDS, Google Cloud SQL, Azure Cosmos DB.

7.6 RDBMS

A Relational Database Management System (RDBMS) is a type of DBMS that stores data in tables (relations) and uses SQL (Structured Query Language) for data manipulation. RDBMSs enforce data integrity through constraints and support relationships between tables using keys.

Key Features of RDBMS

  • Table-Based Storage: Data is organized into rows and columns, with each table representing an entity.
  • Structured Query Language (SQL): A standardized language for defining, querying, and manipulating data.
  • Data Integrity: Enforced through constraints like PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, and CHECK.
  • Relationships: Tables are linked using keys — one-to-one, one-to-many, and many-to-many relationships.
  • Normalization: A process to minimize redundancy and dependency by organizing data into related tables.
  • ACID Compliance: Ensures reliable transaction processing with Atomicity, Consistency, Isolation, and Durability.
  • Views and Indexes: Views provide virtual tables for simplified queries; indexes improve query performance.

SQL Categories

  • DDL (Data Definition Language): CREATE, ALTER, DROP — define database structure.
  • DML (Data Manipulation Language): INSERT, UPDATE, DELETE, SELECT — manipulate data.
  • DCL (Data Control Language): GRANT, REVOKE — manage user permissions.
  • TCL (Transaction Control Language): COMMIT, ROLLBACK, SAVEPOINT — manage transactions.

Popular RDBMS

  • MySQL: Open-source, widely used in web applications (LAMP stack).
  • PostgreSQL: Advanced open-source RDBMS with extensive features.
  • Oracle Database: Enterprise-grade RDBMS with high performance and security.
  • Microsoft SQL Server: Integrated with Microsoft ecosystem, excellent for Windows-based applications.
  • MariaDB: Fork of MySQL with enhanced performance and features.

7.7 Database Applications

Databases are fundamental to virtually every modern application and industry. They enable efficient data management, decision-making, and operational efficiency across various sectors.

Business and Enterprise

  • Enterprise Resource Planning (ERP): SAP, Oracle ERP — integrate business processes (finance, HR, supply chain).
  • Customer Relationship Management (CRM): Salesforce, Microsoft Dynamics — manage customer interactions and data.
  • Inventory Management: Track stock levels, orders, and supply chain operations.
  • Financial Systems: Banking, accounting, and trading platforms require high-performance, secure databases.

Healthcare

  • Electronic Health Records (EHR): Store patient medical histories, diagnoses, and treatment plans.
  • Medical Research: Manage clinical trial data, genomic data, and epidemiological studies.
  • Hospital Management Systems: Appointment scheduling, billing, and resource management.

Education

  • Student Information Systems: Manage student records, grades, and attendance.
  • Learning Management Systems (LMS): Canvas, Moodle — store course content, student progress, and assessments.
  • Research Databases: Academic research data, library catalogs, and publication repositories.

E-Commerce and Retail

  • Product Catalogs: Store product details, pricing, and inventory.
  • Order Processing: Manage customer orders, payments, and shipping.
  • Customer Data: Store customer profiles, preferences, and purchase history for personalization.

Other Applications

  • Social Media: Manage user profiles, posts, messages, and social graphs (often using NoSQL).
  • Telecommunications: Manage subscriber data, call logs, and network configuration.
  • Government: Tax records, voter registration, public services, and national databases.
  • Internet of Things (IoT): Collect and analyze sensor data from connected devices.
