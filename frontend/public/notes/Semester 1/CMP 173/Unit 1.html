1.1 Web Basics

Web technology encompasses the tools, protocols, and systems used to create, manage, and access content on the Internet. It forms the foundation of how information is shared and accessed online, enabling everything from simple websites to complex web applications.

🌐 Purpose
Enable global information sharing, communication, and access to resources through standardized protocols and technologies.
🧩 Components
Clients (browsers), servers (web servers), protocols (HTTP/HTTPS), and content (HTML, CSS, JavaScript).

1.1.1 Internet, Intranet, WWW

  • Internet: A global network of interconnected computers that communicate using standardized protocols (TCP/IP). Enables worldwide data exchange.
  • Intranet: A private network within an organization, using Internet technologies to share information securely among employees. Access is restricted to authorized users.
  • WWW (World Wide Web): A service on the Internet that allows users to access interlinked documents (web pages) via browsers using HTTP/HTTPS. The Web is a subset of the Internet.

1.1.2 Static and Dynamic Web Pages

  • Static Web Page: Fixed content delivered as pre-built HTML files. Content is the same for every user unless manually updated.
    • Pros: Fast loading, simple to create, low server load.
    • Cons: No interactivity, difficult to update.
    • Examples: Company brochure sites, landing pages.
  • Dynamic Web Page: Content generated in real-time using server-side scripts and databases. Customized for each user.
    • Pros: Interactive, personalized, easy to update.
    • Cons: Slower loading, higher server load.
    • Examples: Social media feeds, e-commerce sites, search results.

1.1.3 Web Clients

  • Definition: Software or devices that request and display content from web servers.
  • Function: Send HTTP requests and render HTML responses.
  • Types:
    • Web Browsers: Chrome, Firefox, Safari, Edge, Brave.
    • Mobile Apps: Apps that consume web APIs (REST, GraphQL).
    • IoT Devices: Smart TVs, voice assistants (Alexa, Google Home).

1.1.4 Web Servers

  • Definition: Hardware or software systems that store, process, and deliver web content to clients.
  • Function: Receive HTTP requests, process them, and send HTTP responses.
  • Popular Web Servers:
    • Apache: Most widely used, open-source.
    • Nginx: High performance, event-driven.
    • Microsoft IIS: Windows-based, integrates with .NET.
    • Node.js: JavaScript-based server-side runtime.
💡 Key insight: The Web is built on a client-server model where clients request resources and servers respond with content. Understanding this interaction is fundamental to web development.

1.2 Client-Server Architecture

Client-server architecture is a distributed system model where clients request services or resources from servers over a network. This architecture is the foundation of most web applications and enterprise systems.

Client-Server Model:
┌────────────┐                    ┌────────────┐
│   Client   │ ── Request ──────> │   Server   │
│  (Browser) │ <── Response ───── │ (Web App)  │
└────────────┘                    └────────────┘

1.2.1 Single-Tier Architecture

  • Description: All components (client, server, database) are on a single system.
  • Characteristics: Simple, self-contained, no network dependency.
  • Pros: Easy to develop, no network overhead.
  • Cons: No scalability, limited to single user.
  • Examples: Desktop calculator app, local database on a single PC.

1.2.2 Two-Tier Architecture

  • Description: Client handles presentation and business logic; server handles data storage.
  • Characteristics: Client-server direct communication, typically using database APIs.
  • Pros: Centralized data, better than single-tier.
  • Cons: Limited scalability, logic tied to client.
  • Examples: Desktop application querying a database server, client-server banking apps.

1.2.3 Multi-Tier (N-Tier) Architecture

  • Description: Divides functionality into three or more layers: presentation (client), application logic (middleware), and data (database).
  • Characteristics: Separation of concerns, scalability, maintainability.
  • Pros: Highly scalable, flexible, easier maintenance.
  • Cons: Complex, higher development cost.
  • Examples: E-commerce platforms, enterprise ERP systems, modern web applications.

1.3 HTTP: HTTP Request and Response

HTTP (HyperText Transfer Protocol) is the foundation of data communication on the World Wide Web. It is a request-response protocol that defines how messages are formatted and transmitted between clients and servers.

HTTP Request

  • Definition: A message sent by the client to the server to request a resource or perform an action.
  • Components:
    • Request Line: Method, URL, HTTP version (e.g., GET /index.html HTTP/1.1)
    • Headers: Metadata like Host, User-Agent, Accept, Authorization.
    • Body: Optional data (for POST, PUT requests).
  • Common HTTP Methods:
    • GET: Retrieve a resource.
    • POST: Submit data to be processed.
    • PUT: Update a resource.
    • DELETE: Delete a resource.
    • PATCH: Partial update.
    • HEAD: Retrieve headers only.

HTTP Response

  • Definition: A message sent by the server in reply to a client request.
  • Components:
    • Status Line: HTTP version, Status Code, Status Message (e.g., HTTP/1.1 200 OK)
    • Headers: Content-Type, Content-Length, Set-Cookie, etc.
    • Body: The requested resource (HTML, JSON, image, etc.).
  • Common Status Codes:
    • 2xx Success: 200 OK, 201 Created
    • 3xx Redirection: 301 Moved Permanently, 302 Found
    • 4xx Client Error: 404 Not Found, 401 Unauthorized
    • 5xx Server Error: 500 Internal Server Error, 503 Service Unavailable
// Example HTTP Request
GET /api/users/123 HTTP/1.1
Host: example.com
Authorization: Bearer token123
Accept: application/json

// Example HTTP Response
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 45

{"id":123,"name":"Alice","email":"alice@example.com"}
🌐 Key insight: HTTP is stateless — each request is independent. State management is handled using cookies, sessions, or tokens.

1.4 URL

URL (Uniform Resource Locator) is a web address that specifies the location of a resource on the Internet. It is a standardized way to identify resources like web pages, images, files, or APIs.

URL Structure

URL: https://www.example.com:443/path/to/page?name=value&key=value#section

Parts:
├── https://   → Protocol/Scheme
├── www.example.com → Domain Name
├── :443      → Port (optional)
├── /path/to/page → Path
├── ?name=value&key=value → Query String (optional)
└── #section   → Fragment (optional)

URL Components

  • Protocol: http, https, ftp, file, etc. Specifies how to access the resource.
  • Domain Name: Human-readable name of the server (e.g., google.com).
  • Port: Optional (default: 80 for HTTP, 443 for HTTPS).
  • Path: Location of the resource on the server.
  • Query String: Key-value pairs for parameters (starts with ?).
  • Fragment: Anchor to a specific part of the page (starts with #).

1.5 Client-Side Scripting

Client-side scripting involves executing scripts in the user's browser to enhance web page interactivity and functionality. It runs on the client machine and does not require server communication for every action.

Key Technologies

  • JavaScript: The primary language for client-side scripting.
  • HTML: Structure of the web page.
  • CSS: Styling and presentation.
  • Frameworks: React, Vue.js, Angular, Svelte.
  • Libraries: jQuery, D3.js, Three.js.

Common Uses

  • Form Validation: Validate user input before submission.
  • Dynamic Content: Update page content without reloading (AJAX).
  • Interactivity: Menus, animations, drag-and-drop, modal dialogs.
  • User Interface: Responsive designs, interactive dashboards.
  • API Communication: Fetch data from servers using fetch() or Axios.
// Client-side JavaScript example
document.getElementById('btn').addEventListener('click', function() {
    const name = document.getElementById('name').value;
    if (name.length < 2) {
        alert('Name must be at least 2 characters');
    } else {
        fetch('/api/user', {
            method: 'POST',
            body: JSON.stringify({name: name})
        })
        .then(response => response.json())
        .then(data => console.log(data));
    }
});
⚡ Key insight: Client-side scripting reduces server load by handling interactions locally. However, it should not be relied upon for security-critical operations — server-side validation is essential.

1.6 Server-Side Scripting

Server-side scripting involves executing scripts on the server to generate dynamic web content before sending it to the client. It processes requests, interacts with databases, and produces customized responses.

Key Technologies

  • Languages: PHP, Python (Django/Flask), Ruby (Rails), Java (Spring), JavaScript (Node.js), C# (ASP.NET).
  • Frameworks: Express.js, Laravel, Spring Boot, Django, Ruby on Rails.
  • Databases: MySQL, PostgreSQL, MongoDB, Redis.

Common Uses

  • Data Processing: Process form data, handle file uploads.
  • Database Operations: Query, insert, update, delete data.
  • Authentication: User login, registration, session management.
  • API Development: RESTful APIs, GraphQL endpoints.
  • Business Logic: Process payments, calculate shipping costs, apply business rules.
  • Security: Input validation, sanitization, encryption.
// Server-side example (Node.js/Express)
const express = require('express');
const app = express();

app.get('/users/:id', async (req, res) => {
    try {
        const user = await db.users.findById(req.params.id);
        if (!user) {
            return res.status(404).json({error: 'User not found'});
        }
        res.json(user);
    } catch (error) {
        res.status(500).json({error: error.message});
    }
});

1.7 Web 1.0, Web 2.0, and Web 3.0

The evolution of the World Wide Web is categorized into three distinct phases, each characterized by different technologies, user interactions, and philosophies.

Web 1.0 (The Static Web) — 1990s

  • Characteristics: Static, read-only web.
  • Content: Information delivery, text-heavy, limited multimedia.
  • Interaction: One-way communication (publisher → reader).
  • Technologies: HTML, HTTP, basic CSS, static pages.
  • Examples: Personal web pages, company brochures, early news sites.
  • Users: Consumers of content.

Web 2.0 (The Social Web) — 2000s

  • Characteristics: Interactive, user-driven web.
  • Content: User-generated content, multimedia, social media.
  • Interaction: Two-way communication, collaboration, sharing.
  • Technologies: AJAX, JavaScript frameworks, CSS3, HTML5, APIs.
  • Examples: Facebook, YouTube, Wikipedia, Twitter, Instagram.
  • Users: Content creators and consumers.

Web 3.0 (The Semantic Web) — 2010s onwards

  • Characteristics: Decentralized, AI-driven, semantic web.
  • Content: Machine-readable, interconnected data, personalization.
  • Interaction: Intelligent, context-aware, personalized experiences.
  • Technologies: Blockchain, AI/ML, IoT, Edge Computing, Semantic Web standards.
  • Examples: Decentralized apps (dApps), smart contracts, NFT platforms, AI assistants.
  • Users: Active participants in a decentralized ecosystem.
