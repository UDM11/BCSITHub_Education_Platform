7.1 Scope and Closures

Scope determines the accessibility of variables, while closures allow functions to retain access to their outer scope's variables even after the outer function has finished executing.

📦 Scope
Defines where variables are accessible. Types: Global, Function, Block (let/const). Lexical scope follows the nesting structure.
🔒 Closures
A function bundled with its lexical environment. Retains access to variables from its parent scope even after the parent function returns.

Scope Types

  • Global Scope: Variables declared outside any function. Accessible everywhere.
  • Function Scope: Variables declared inside a function (with var). Accessible within that function.
  • Block Scope: Variables declared with let and const. Accessible within the block { }.
// Global scope
let globalVar = 'Global';

function outer() {
    let outerVar = 'Outer'; // Function scope

    if (true) {
        let blockVar = 'Block'; // Block scope (let)
        var functionScoped = 'Function'; // Function scope (var)
    }

    return function inner() {
        console.log(globalVar); // Accessible
        console.log(outerVar); // Accessible
        console.log(blockVar); // Not accessible (block scope)
        console.log(functionScoped); // Accessible
    };
}

Closures in Practice

// Closure example - counter
function createCounter() {
    let count = 0;
    return function() {
        return ++count;
    };
}

const counter1 = createCounter();
console.log(counter1()); // 1
console.log(counter1()); // 2

const counter2 = createCounter();
console.log(counter2()); // 1 (independent closure)

// Closure with parameters
function multiplier(factor) {
    return function(number) {
        return number * factor;
    };
}

const double = multiplier(2);
const triple = multiplier(3);
console.log(double(5)); // 10
console.log(triple(5)); // 15

Use Cases for Closures

  • Data Privacy: Create private variables.
  • Event Handlers: Preserve state in event callbacks.
  • Function Factories: Generate functions with pre-configured behavior.
  • Module Pattern: Create encapsulated modules.
🔑 Key insight: Closures are a fundamental JavaScript concept. They enable data encapsulation, functional programming, and many design patterns.

7.2 Error Handling and Debugging

Error handling manages runtime errors gracefully, while debugging helps identify and fix issues in code.

try/catch/finally

  • try: Block where errors might occur.
  • catch: Handles errors thrown in try block.
  • finally: Executes regardless of whether an error occurred.

throw Statement

  • Creates custom errors: throw new Error('Custom error');
  • Can throw any value: throw 'Something went wrong';

Debugging Techniques

  • console.log(): Output values for inspection.
  • debugger: Pauses execution and opens developer tools.
  • Breakpoints: Set in browser DevTools.
  • console.table(): Display arrays/objects in tabular format.
  • console.trace(): Show call stack.
// try/catch/finally example
try {
    let data = JSON.parse('{ invalid JSON }');
    console.log(data);
} catch (error) {
    console.error('Parsing error:', error.message);
} finally {
    console.log('This always executes');
}

// Custom error
function divide(a, b) {
    if (b === 0) {
        throw new Error('Division by zero is not allowed');
    }
    return a / b;
}

try {
    divide(10, 0);
} catch (error) {
    console.error(error.message);
}

// Debugging
function calculate() {
    let x = 10;
    let y = 20;
    debugger; // Execution pauses here in DevTools
    console.log(x + y);
}

// Console methods
console.table([{name: 'John', age: 30}, {name: 'Jane', age: 25}]);
console.trace('Function call trace');

Error Types

  • SyntaxError — Invalid syntax.
  • ReferenceError — Variable not defined.
  • TypeError — Invalid type operation.
  • RangeError — Value out of range.
  • URIError — Invalid URI handling.

7.4 Asynchronous JavaScript

Asynchronous JavaScript handles operations that take time (e.g., network requests, file I/O, timers) without blocking the main execution thread.

Callbacks

  • Functions passed as arguments to be executed later.
  • Callback Hell: Nested callbacks that become hard to read and maintain.

Promises

  • Objects representing eventual completion or failure of an async operation.
  • States: Pending, Fulfilled, Rejected.
  • Chainable with .then(), .catch(), .finally().

async/await

  • Syntactic sugar over Promises.
  • Makes async code look synchronous.
  • Use try/catch for error handling.
// Callback example
function fetchData(callback) {
    setTimeout(() => {
        callback({ data: 'Hello World' });
    }, 1000);
}

fetchData(function(result) {
    console.log(result.data);
});

// Promise example
function fetchDataPromise() {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            resolve({ data: 'Hello World' });
        }, 1000);
    });
}

fetchDataPromise()
    .then(result => console.log(result.data))
    .catch(error => console.error(error))
    .finally(() => console.log('Done'));

// async/await example
async function getData() {
    try {
        let result = await fetchDataPromise();
        console.log(result.data);
    } catch (error) {
        console.error(error);
    }
}

getData();

// Promise.all - parallel execution
Promise.all([
    fetchDataPromise(),
    fetchDataPromise()
]).then(results => {
    console.log(results[0].data, results[1].data);
});

7.5 JSON and AJAX

JSON (JavaScript Object Notation) is a lightweight data format for data exchange. AJAX (Asynchronous JavaScript and XML) enables asynchronous data fetching without page refresh.

JSON

  • JSON.stringify(): Convert JavaScript object to JSON string.
  • JSON.parse(): Convert JSON string to JavaScript object.
  • Format: Keys must be in double quotes.

AJAX with fetch()

  • fetch() returns a Promise.
  • Response: Use .json(), .text(), etc.
  • Options: method, headers, body, etc.
// JSON example
let person = { name: 'John', age: 30, city: 'New York' };
let jsonString = JSON.stringify(person);
console.log(jsonString); // '{"name":"John","age":30,"city":"New York"}'

let parsed = JSON.parse(jsonString);
console.log(parsed.name); // John

// GET request with fetch
fetch('https://api.example.com/users')
    .then(response => {
        if (!response.ok) {
            throw new Error('Network response was not ok');
        }
        return response.json();
    })
    .then(data => console.log(data))
    .catch(error => console.error('Error:', error));

// POST request with fetch
fetch('https://api.example.com/users', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({ name: 'Alice', age: 25 })
})
    .then(response => response.json())
    .then(data => console.log('Created:', data))
    .catch(error => console.error('Error:', error));

// async/await with fetch
async function fetchUsers() {
    try {
        let response = await fetch('https://api.example.com/users');
        let data = await response.json();
        console.log(data);
    } catch (error) {
        console.error('Error:', error);
    }
}

XMLHttpRequest (Legacy)

let xhr = new XMLHttpRequest();
xhr.open('GET', 'https://api.example.com/data');
xhr.onload = function() {
    if (xhr.status === 200) {
        console.log(JSON.parse(xhr.responseText));
    }
};
xhr.send();

7.8 JavaScript Best Practices

Following best practices ensures clean, maintainable, and performant JavaScript code.

Best Practices

  • Use let and const: Avoid var. Use const by default, let when reassignment is needed.
  • Use Strict Equality: Prefer === over == to avoid type coercion.
  • Avoid Global Variables: Minimize pollution of the global namespace.
  • Use Arrow Functions: For concise and predictable this binding.
  • Handle Errors: Always catch exceptions, especially in async code.
  • Write Descriptive Names: Use meaningful variable and function names.
  • Keep Functions Small: Each function should do one thing.
  • Use Modern Features: Destructuring, spread, optional chaining, nullish coalescing.
  • Format Code: Use Prettier or ESLint for consistent formatting.
// Good practices
const MAX_USERS = 100; // Constants in uppercase

function getUserData(userId) {
    return fetch(`/api/users/${userId}`)
        .then(response => {

            }
            return response.json();
        })
        .catch(error => {
            console.error('Error fetching user:', error);
            throw error;
        });
}

// Using modern features
