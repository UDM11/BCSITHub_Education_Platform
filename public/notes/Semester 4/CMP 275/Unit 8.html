8.1 The Memory Hierarchy and Cache Memory

A computer's memory system is organized as a hierarchy to optimize performance, capacity, and cost per bit. As we go down the hierarchy, access speed decreases, storage capacity increases, and cost per bit decreases:

  1. CPU Registers: Temporary storage inside the CPU. Fastest access time (sub-nanosecond), capacity up to a few hundred bytes.
  2. Cache Memory (L1, L2, L3): Implemented using high-speed Static RAM (SRAM). Stores recently accessed instruction blocks to speed up execution.
  3. Primary/Main Memory (RAM & ROM): Implemented using Dynamic RAM (DRAM). Holds active programs and data currently being processed. ROM holds system initialization code (BIOS/UEFI).
  4. Auxiliary Memory (SSD, Magnetic Disk, Tape): Non-volatile, high-capacity, low-cost secondary storage. Used for long-term file storage.
Locality of Reference: The memory hierarchy is effective because of the Locality of Reference principle. Programs tend to access instructions and data near locations they have recently accessed (temporal and spatial locality).

8.2 Primary Memory and Address Decoding

Memory chips require addressing and selection lines to read and write data. Address Decoding is the process of generating chip select (CS) signals from the CPU address bus to enable the correct memory chip.

Address Decoding Example:

Design a memory system with a 16-bit address bus (A0-A15) containing:
- Two 1024x8 RAM chips (RAM 1 and RAM 2).
- One 2048x8 ROM chip.

Required Address Lines per Chip:
- RAM chips: 1024 bytes = 2^10, so they require 10 address lines (A0-A9).
- ROM chip: 2048 bytes = 2^11, so it requires 11 address lines (A0-A10).

Memory Address Map:

Component A15 - A12 A11 A10 A9 - A0 Address Range (Hex)
RAM 1 0 0 0 0 0 0 0000000000 to 1111111111 0000H - 03FFH
RAM 2 0 0 0 0 0 1 0000000000 to 1111111111 0400H - 07FFH
ROM 0 0 0 0 1 X 0000000000 to 1111111111 0800H - 0FFFH

Decoding Logic Equations:

We use address lines A15-A11 to select the chips:
- General Select (all chips require A15-A12 = 0000): GS = A15' & A14' & A13' & A12'
- RAM 1 Chip Select: CS1 = GS & A11' & A10'
- RAM 2 Chip Select: CS2 = GS & A11' & A10
- ROM Chip Select: CS3 = GS & A11

8.3 Virtual Memory and Page Replacement

Virtual Memory is an address mapping scheme that gives programs the illusion of having a large, contiguous memory space, even if the physical RAM is small and fragmented. The physical addresses in RAM are mapped to logical addresses used by the program.

Address Translation:

The CPU generates a Virtual Address consisting of a Page Number and a Line Offset. The Memory Management Unit (MMU) translates it to a Physical Address (Block Frame Number + Line Offset) using a Page Table:

Virtual Address: [ Page Number (p) ] [ Offset (d) ] | | v | +---------------+ | | Page Table | | +---------------+ | | p -> Frame (f)| | +-------+-------+ | | | v v Physical Address: [ Frame Number (f) ] [ Offset (d) ]

8.4 Memory Management Hardware

The **Memory Management Unit (MMU)** handles address translation and protection at runtime:

  • Segmented Page Mapping: Logical memory is divided into segments (e.g., Code, Data, Stack) based on program logic. Each segment is further divided into fixed-size pages. This provides logical organization and efficient physical allocation.
  • Memory Protection: Prevents programs from accessing unauthorized memory regions (e.g., preventing user programs from writing to OS memory). It uses base/limit registers or access-control bits in page tables to enforce protection.
