5.1 Control Unit Architecture: Hardwired vs. Microprogrammed

The Control Unit (CU) directs all operations inside the CPU by issuing appropriate control signals. There are two primary techniques for implementing the CU:

1. Hardwired Control Unit:

Implemented using combinational logic gates, counters, and decoders.
Timing Signals: An instruction opcode (e.g., bits 12-14 in IR) is decoded by a 3x8 decoder into one of eight outputs (D0-D7). A 4-bit Sequence Counter (SC) feeds a 4x16 decoder to produce 16 timing states (T0-T15). Control logic gates combine these decoded inputs to generate control outputs at specific clock ticks.

+------------+ +------------+ | Instruction| | Sequence | | Register | | Counter | +-----+------+ +-----+------+ | (Opcode Bits) | v v [3x8 Decoder] [4x16 Decoder] (D0 to D7) (T0 to T15) | | +----------+ +----------+ | | v v +---------------+ | Control Logic |-----------> Output Control Signals | Gates | +---------------+

2. Microprogrammed Control Unit:

Implemented by executing sequences of microcode stored in a Control Memory (ROM).

+-----------------------------+ | Address Sequencer | +--------------+--------------+ | (Next address) v +-----------------------------+ | Control Address Reg (CAR) | +--------------+--------------+ | v +-----------------------------+ | Control Memory (ROM) | +--------------+--------------+ | v +-----------------------------+ | Control Buffer Reg (CBR) | +--------------+--------------+ | | v (Control Signals) v (Address Field for next step)

Detailed Comparison Table:

Characteristic Hardwired Control Unit Microprogrammed Control Unit
Implementation Hardware gates, decoders, flip-flops. Microprogram stored in Control ROM.
Operational Speed Extremely fast (no memory access delay). Slower (requires reading from Control Memory).
Design Complexity High. Difficult to layout and debug. Low. Highly structured and systematic.
Instruction Expansion Difficult (requires rewiring the chip). Easy (requires writing new microcode).
Cost High for custom IC structures. Lower due to standardized ROM grids.
Use Case RISC Processors (e.g., MIPS, ARM). CISC Processors (e.g., x86 family).

5.2 Microprogramming Concepts & Addressing Sequences

A microprogram is a sequence of control words (microinstructions) that execute a macroinstruction. The Address Sequencer determines the address of the next microinstruction to fetch:

Address Sequencing Sources:

  1. Incrementing CAR: The CAR is incremented by 1 (default next step).
  2. Branching: If conditional flags are met, jump to an address specified in the address field of the microinstruction.
  3. Mapping: Translate the macroinstruction opcode into a control memory address.
    Mapping Example: If opcode is 1011, mapping logic inserts a 0 at the start and 00 at the end to create a 7-bit Control Address: 0101100.
  4. Subroutine Call/Return: Fetch address from return registers (SBR).

5.3 Symbolic and Binary Microprogramming

A microinstruction format is divided into fields. A typical 20-bit microinstruction layout is:

Microinstruction Format: +--------+--------+--------+---------------+-------------+------------------+ | F1 (3) | F2 (3) | F3 (3) | CD (2 bits) | BR (2 bits) | AD (7 bits) | +--------+--------+--------+---------------+-------------+------------------+ F1, F2, F3: Micro-operation fields (Decoded) CD: Condition Select (00=Always, 01=Carry, 10=Zero, 11=Sign) BR: Branch Field (00=Jump, 01=Call, 10=Return, 11=Map) AD: Address Field (Holds target Control Address)

Symbolic Microprogram Example (FETCH and ADD):

Here is a symbolic representation of the microinstructions:


// FETCH SEQUENCE:
Address   Micro-operations     CD   BR    AD
0000000   ORG 0                ; Start at address 0
          ART, PCT             U    JMP   NEXT   ; AR <- PC
          DRT, INC             U    JMP   NEXT   ; DR <- Memory, PC <- PC+1
          IRT                  U    MAP          ; IR <- DR, Jump to Map address

// ADD EXECUTION SEQUENCE (Opcode mapped to address 64):
0100000   ORG 64               ; Add instruction address
          ART                  U    JMP   NEXT   ; AR <- Address field of IR
          DRT                  U    JMP   NEXT   ; DR <- Memory
          ADD, LaT             U    JMP   FETCH  ; AC <- AC + DR, Return to Fetch

Corresponding Binary Microprogram Table:

Microinstruction Description F1 F2 F3 CD BR AD (Address)
AR <- PC 010 000 000 00 00 0000001
DR <- Memory, PC <- PC + 1 000 100 000 00 00 0000010
IR <- DR, Map Opcode 000 000 110 00 11 0000000
AC <- AC + DR, Jump Fetch 001 000 001 00 00 0000000

5.4 Addressing Modes

Addressing modes define how the instruction calculates the actual memory address (Effective Address, EA) of the data operand.

  • Implied Mode: Operand is implied in the instruction (e.g., CMA, EA not needed).
  • Immediate Mode: Operand is specified directly in the instruction (e.g., ADD 5, EA = Address of operand field).
  • Register Mode: Operand is in a register (e.g., ADD R1, EA = R1).
  • Register Indirect Mode: Register contains the address of the operand (e.g., ADD (R1), EA = M[R1]).
  • Direct Addressing Mode: Instruction contains the memory address of the operand (e.g., ADD 2500H, EA = 2500H).
  • Indirect Addressing Mode: Instruction contains an address that points to the actual address of the operand (e.g., ADD [2500H], EA = M[2500H]).
  • Relative Addressing Mode: Address is calculated relative to the Program Counter (e.g., JMP +10, EA = PC + 10).
  • Indexed Addressing Mode: Effective address is calculated by adding an offset to an Index Register (e.g., ADD X(R1), EA = X + R1).

5.5 RISC vs. CISC Design Philosophy

CPU design strategies are divided into CISC and RISC:

  • CISC (Complex Instruction Set Computer):
    • Concept: Minimizes instructions per program at the expense of cycles per instruction. It supports high-level complex operations directly in assembly.
    • Hardware: Relies heavily on microprogrammed control units to decode instructions. Fewer general registers are available.
  • RISC (Reduced Instruction Set Computer):
    • Concept: Minimizes clock cycles per instruction by simplifying instructions. Each instruction executes in exactly 1 cycle.
    • Hardware: Relies on hardwired control units. Uses a large register file to minimize memory reads. Excellent for pipelining.
