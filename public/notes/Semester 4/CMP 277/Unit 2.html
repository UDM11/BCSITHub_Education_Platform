2.1 Network Definitions, Classification and Topologies

What is a Computer Network?

A computer network is a collection of autonomous computers and devices interconnected by communication channels to facilitate data sharing, resource sharing, and communication. Networks range from personal area connections to the global Internet.

Uses and Benefits of Computer Networks

  • Resource Sharing: Sharing physical devices (printers, scanners, storage servers) and logical resources (databases, applications, files) among network users.
  • Information Sharing: Instantaneous transfer of files, reports, and emails across geographical distances.
  • Enhanced Communication: Instant messaging, video conferencing, IP telephony, and collaborative workflows.
  • High Reliability: Crucial data can be replicated on multiple machines, ensuring system availability if one hardware component fails.
  • Cost Reduction: Storing shared resources on central servers reduces the cost of purchasing individual licenses or redundant peripherals.
  • Scalability: System capacity can be expanded easily by adding more nodes (computers) without interrupting existing network configurations.

Network Topologies

Network topology refers to the geometric arrangement of links and nodes in a network. It can be viewed physically (cable layout) or logically (data flow path).

1. Mesh Topology

Every node is connected to every other node in the network via a dedicated point-to-point link.

  • Cables Required (Full Mesh): $N(N-1)/2$ lines, where $N$ is the number of nodes.
  • I/O Ports Required per Node: $N-1$ ports.
  • Advantages: High redundancy, robust (fault isolated), secure.
  • Disadvantages: Extremely expensive, high cabling complexity.
       Full Mesh (4 Nodes):
             Node A ─────── Node B
               │   \       /   │
               │    \     /    │
               │     \   /     │
               │      \ /      │
               │       X       │
               │      / \      │
               │     /   \     │
               │    /     \    │
             Node C ─────── Node D

2. Star Topology

Each node connects directly to a central controller (typically a Hub or Switch). Nodes do not communicate directly with one another.

  • Cables Required: $N$ lines.
  • Advantages: Easy to configure, low cost, single cable failure doesn't affect others.
  • Disadvantages: Single point of failure (if central hub fails, the whole network goes down).
       Star Topology:
               Node A     Node B
                 │         │
                 ▼         ▼
             ┌─────────────────┐
             │ Central Switch  │
             └─────────────────┘
                 ▲         ▲
                 │         │
               Node C     Node D

3. Bus Topology

A multipoint configuration where one long cable (the backbone) acts as a shared link. Taps connect nodes to the backbone, and terminators are placed at the ends to prevent signal reflection.

  • Advantages: Cheap, easy installation, minimal cabling.
  • Disadvantages: Difficult reconfiguration, backbone failure disables the network, collision issues.
       Bus Topology:
       [Terminator] ═══╦═════════╦═════════╦═════════╦═══ [Terminator]
                       ║         ║         ║         ║
                     Node A    Node B    Node C    Node D

4. Ring Topology

Each node has a dedicated point-to-point connection with only the two nodes on either side. Signals pass along the loop in one direction (using tokens to regulate transmission).

  • Advantages: Simple installation, predictable token access delay.
  • Disadvantages: Unidirectional traffic means a single break in the loop halts the entire network.
       Ring Topology:
             Node A ─────── Node B
               │             │
               │             │
             Node C ─────── Node D

5. Hybrid Topology

A combination of two or more distinct topologies. For example, a Star-Bus network where several star networks are linked via a bus backbone.

2.2 Client-Server vs. Peer-to-Peer, Protocols and Standards

Client/Server Architecture

An architecture in which one or more computers (servers) are dedicated to providing resources, services, and data management to other computers (clients) on the network.

  • Role of Server: Always active, listens for client requests, manages permissions.
  • Role of Client: Active only when initiating requests, relies on server for files/services.
  • Advantages: Centralized management, easy backup, robust security.
  • Disadvantages: High cost, requires skilled admin, server overload bottlenecks performance.

Peer-to-Peer (P2P) Architecture

An architecture where every computer (peer) on the network has equal capabilities and responsibilities. Peers act as both clients and servers to other nodes.

  • Advantages: Low cost, no central server required, easy to set up, highly scalable.
  • Disadvantages: Centralized administration is impossible, security is difficult, backup must be done on each node.

Protocols and Standards

  • Protocol: A set of syntax, semantics, and timing rules governing communication.
    • Syntax: Structure or format of data (e.g., first 8 bits = sender address).
    • Semantics: Interpretation of bits (e.g., does "101" mean print or delete?).
    • Timing: When to send data and how fast it should be sent.
  • Standards: Documented agreements that ensure interoperability.
    • De Facto standards: Standards by custom or common use (e.g., TCP/IP).
    • De Jure standards: Standards established by formal legislated bodies (e.g., ISO, IEEE, ITU-T).

2.3 OSI and TCP/IP Reference Models

The OSI 7-Layer Reference Model

Developed by the International Organization for Standardization (ISO) in 1984, the Open Systems Interconnection (OSI) model is a conceptual framework that standardizes network communications into seven logical layers. 

  ┌────────────────────────────────────────────────────────┐
  │ 7. Application  ── Interface for user programs         │  PDU: Data
  ├────────────────────────────────────────────────────────┤
  │ 6. Presentation ── Encryption, syntax translation      │  PDU: Data
  ├────────────────────────────────────────────────────────┤
  │ 5. Session      ── Interhost dialog management         │  PDU: Data
  ├────────────────────────────────────────────────────────┤
  │ 4. Transport    ── End-to-end reliability, segmenting  │  PDU: Segment
  ├────────────────────────────────────────────────────────┤
  │ 3. Network      ── Logical routing, IP addresses       │  PDU: Packet
  ├────────────────────────────────────────────────────────┤
  │ 2. Data Link    ── Physical framing, MAC addresses     │  PDU: Frame
  ├────────────────────────────────────────────────────────┤
  │ 1. Physical     ── Binary transmission (bits on wire)  │  PDU: Bits
  └────────────────────────────────────────────────────────┘

OSI Layer Functions

  1. Physical Layer: Coordinates transmission of unstructured raw bit streams over physical media. Deals with voltage levels, data rates, cables, and pin layouts.
  2. Data Link Layer: Organizes raw bits into frames. Provides node-to-node delivery, error control (CRC), flow control, and access control (MAC addresses).
  3. Network Layer: Routes packets across multiple networks. Responsible for source-to-destination routing, logical addressing (IP addresses), and fragmentation.
  4. Transport Layer: Splits data into segments. Provides end-to-end flow control, error recovery, port addressing, and connection management (TCP/UDP).
  5. Session Layer: Establishes, maintains, and synchronizes conversations between applications.
  6. Presentation Layer: Resolves syntax differences. Handles data formatting, compression, translation, and encryption/decryption.
  7. Application Layer: Acts as the entry point for application software to access network services (HTTP, DNS, SMTP).

OSI vs. TCP/IP Comparison

Feature OSI Model TCP/IP Model
Number of Layers 7 Layers 4 or 5 Layers
Introduction Developed by ISO (1984) Developed by ARPANET/DoD (prior to OSI)
Philosophy Strictly conceptual, prescriptive Practical, protocol-driven
Upper Layers Application, Presentation, Session are separate Merged into a single Application Layer
Lower Layers Data Link and Physical separate Merged as Network Access Layer (in 4-layer model)

2.4 Networking Hardware and Troubleshooting Commands

Networking Hardware Components

  • Network Interface Card (NIC): A hardware component (internal or USB) that connects a device to the transmission medium. Every NIC has a unique 48-bit physical address burned into its ROM, known as the MAC Address.
  • Hub: A Layer 1 multiport repeater. It receives an electrical signal on one port and blindly broadcasts it to all other ports.
    Creates a single large collision domain and broadcast domain.
  • Repeater: A Layer 1 device used to regenerate electrical signals that have faded due to attenuation, extending the physical length of the network segment.
  • Switch: A Layer 2 intelligent device. It reads incoming frames' destination MAC addresses and forwards them only to the specific port connected to that destination node.
    Each port of a switch is a separate collision domain. All ports share a single broadcast domain.
  • Bridge: A legacy Layer 2 device with fewer ports than a switch, used to connect two separate LAN segments.
  • Router: A Layer 3 device that routes packets between different networks based on logical addresses (IP addresses). It determines the best path for data to travel.
    Routers block broadcasts. Each router interface is a separate collision domain and broadcast domain.

2.5 Deep Dive: Collision Domains vs. Broadcast Domains

Understanding the difference between collision domains and broadcast domains is crucial for effective network design and troubleshooting:

  • Collision Domain: A logical network segment where data packets can collide with each other when sent on a shared medium. Collisions occur in hubs and half-duplex links. Switches segment networks into separate collision domains per port.
  • Broadcast Domain: A logical division of a computer network in which all nodes can reach each other by broadcast at the data link layer. A broadcast frame is sent to destination MAC FF:FF:FF:FF:FF:FF. Switches forward broadcasts out all ports. Routers block broadcasts, thus defining broadcast domain boundaries.
Device Collision Domains Broadcast Domains Operating OSI Layer
Hub / Repeater 1 (Shared across all ports) 1 (Shared across all ports) Layer 1 (Physical)
Bridge Separate per port (e.g., 2-port bridge = 2 collision domains) 1 (Shared across all ports) Layer 2 (Data Link)
Switch Separate per port (e.g., 24-port switch = 24 collision domains) 1 (Shared across all ports, unless VLANs are configured) Layer 2 (Data Link)
Router Separate per port Separate per port (Blocks broadcasts) Layer 3 (Network)

2.6 Packet Encapsulation and Decapsulation

As data moves down the sending device's OSI stack, each layer adds control information (headers and sometimes trailers) to the data received from the layer above. This process is called encapsulation. 

  [Application Layer]       ─── Data (HTTP, SMTP)
                                   │
                                   ▼  (Add Transport Header)
  [Transport Layer]         ─── Segment (TCP) / Datagram (UDP)
                                   │
                                   ▼  (Add Network Header)
  [Network Layer]           ─── Packet (IP)
                                   │
                                   ▼  (Add Link Header & Trailer)
  [Data Link Layer]         ─── Frame (Ethernet)
                                   │
                                   ▼  (Convert to electrical/optical signals)
  [Physical Layer]          ─── Bits (0s and 1s)
  1. User Data: The user initiates transmission (e.g., clicks a link). Application data is created.
  2. Segment/Datagram Creation: The Transport layer adds a header containing port numbers, sequencing, and checksums. The unit becomes a Segment (TCP) or Datagram (UDP).
  3. Packet Creation: The Network layer adds a header containing Source and Destination IP addresses. The unit becomes a Packet.
  4. Frame Creation: The Data Link layer wraps the packet with a header containing Source and Destination MAC addresses, and a trailer (FCS/CRC) containing error check sequences. The unit becomes a Frame.
  5. Bit Stream: The Physical layer converts the frame into binary electrical, optical, or electromagnetic signals (bits) and sends them over the transmission medium.
  6. Decapsulation: The reverse process occurs at the receiver. Each layer strips off its respective header, verifies integrity, and passes the payload to the layer above.

2.7 Global Standards Organizations

Standards are essential for ensuring that products from different manufacturers can communicate successfully. The key organizations defining networking standards are:

  • ISO (International Organization for Standardization): Best known for the OSI model.
  • IEEE (Institute of Electrical and Electronics Engineers): Defines LAN/MAN standards, notably the IEEE 802 group:
    • 802.3: Ethernet standards.
    • 802.11: Wireless LAN (Wi-Fi) standards.
    • 802.15: Wireless PAN (Bluetooth, Zigbee).
  • ITU-T (International Telecommunication Union - Telecommunication sector): Defines standards for telecommunication, public mail, and telegraph systems.
  • IETF (Internet Engineering Task Force): A large open international community of network designers, operators, and researchers. They publish standards as RFC (Request for Comments) documents (e.g., RFC 791 for IPv4).
  • ANSI (American National Standards Institute): A non-profit organization coordinating voluntary standards in the US.
