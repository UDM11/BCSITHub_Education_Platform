Unit 8: Software Project Management [4 Hrs.]

8.1 Software Project, Project Manager, Qualities of Project Manager

What is a Software Project?

A software project is a temporary endeavor undertaken to create a unique software product, service, or result. It has a defined beginning and end, specific objectives, scope, budget, and schedule. A software project involves the coordinated effort of a team to deliver software that meets specified requirements within constraints of time, cost, and quality.

Characteristics of Software Projects

  • Temporariness: Every project has a definite start and end date
  • Uniqueness: Each project produces a unique product or result
  • Progressive Elaboration: Details are refined as the project progresses
  • Intangibility: Software is intangible; progress is harder to measure than construction projects
  • Complexity: Software systems can be enormously complex
  • Conformity: Software must conform to the requirements of users, hardware, regulations
  • Changeability: Software requirements are subject to constant change

What is a Project Manager?

A software project manager is the person responsible for planning, executing, monitoring, controlling, and closing a software project. The project manager ensures that the project is completed on time, within budget, and meets quality standards.

Qualities of a Good Project Manager

Category Quality Description
Leadership Vision and Direction Can articulate a clear vision and motivate the team to achieve it
Leadership Decision Making Can make timely decisions with incomplete information
Technical Technical Competence Understands the technology, tools, and methodologies used
Technical Problem Solving Can identify and resolve technical and organizational problems
Communication Effective Communication Can communicate clearly with team members, stakeholders, and management
Communication Negotiation Can negotiate resources, scope, and schedule with stakeholders
Management Planning & Organization Can create and manage realistic project plans
Management Risk Management Can identify, assess, and mitigate risks proactively
People Team Building Can build cohesive, motivated, and productive teams
People Conflict Resolution Can resolve conflicts within the team constructively

Roles and Responsibilities of a PM

  • Define project scope and objectives
  • Create project plans (schedule, budget, resource allocation)
  • Manage project team and assign tasks
  • Monitor project progress and take corrective action
  • Communicate project status to stakeholders
  • Manage risks and resolve issues
  • Ensure quality standards are met
  • Manage project budget and resources
  • Coordinate with external parties (customers, vendors)
  • Facilitate project closure and lessons learned

8.2 Activities in Project Management

The Four P's of Software Project Management

Effective software project management focuses on the four P's:

1. People

People are the most important factor in a successful software project. Key people-related activities include:

  • Stakeholder management: Identifying and managing expectations of all stakeholders
  • Team organization: Structuring teams appropriately (functional, project-based, matrix)
  • Skill management: Ensuring the team has the right skills for the project
  • Motivation: Keeping team members engaged and productive

2. Product

Understanding the product (software) to be built is essential:

  • Define scope and objectives
  • Identify alternative solutions
  • Identify constraints (technical, business, resource)
  • Decompose the product into manageable components

3. Process

The software process framework must be chosen and adapted:

  • Select the appropriate process model (Agile, Waterfall, Spiral, etc.)
  • Define the set of framework activities and task sets
  • Establish umbrella activities (QA, SCM, reviews, risk management)

4. Project

The project itself must be planned and managed:

  • Estimation (cost, effort, schedule)
  • Planning and scheduling
  • Monitoring and control
  • Risk management

Key Management Activities

  1. Proposal Writing: Preparing proposals for project funding/approval
  2. Project Planning & Scheduling: Creating WBS, Gantt charts, network diagrams
  3. Project Costing: Estimating and controlling project costs
  4. Project Monitoring & Reviews: Tracking progress against plans
  5. Personnel Selection & Evaluation: Building and evaluating teams
  6. Report Writing & Presentations: Communicating status and results

8.3 Software Project Planning and Management Plan

Software Project Planning

Project planning is the most important project management activity. A project plan defines the work to be done, the resources needed, the schedule, and the risks. Planning begins before technical work starts and continues iteratively throughout the project.

Work Breakdown Structure (WBS)

A WBS is a hierarchical decomposition of the total scope of work to be carried out by the project team. It breaks the project into deliverable-oriented work packages. 

  WBS Example: E-Commerce Website Project

  1. E-Commerce Website
  ├── 1.1 Project Management
  │   ├── 1.1.1 Project Planning
  │   ├── 1.1.2 Progress Monitoring
  │   └── 1.1.3 Risk Management
  ├── 1.2 Requirements
  │   ├── 1.2.1 Requirements Gathering
  │   ├── 1.2.2 Requirements Analysis
  │   └── 1.2.3 SRS Document
  ├── 1.3 Design
  │   ├── 1.3.1 Architecture Design
  │   ├── 1.3.2 Database Design
  │   ├── 1.3.3 UI/UX Design
  │   └── 1.3.4 API Design
  ├── 1.4 Development
  │   ├── 1.4.1 Frontend Development
  │   ├── 1.4.2 Backend Development
  │   ├── 1.4.3 Database Implementation
  │   └── 1.4.4 Payment Integration
  ├── 1.5 Testing
  │   ├── 1.5.1 Unit Testing
  │   ├── 1.5.2 Integration Testing
  │   ├── 1.5.3 System Testing
  │   └── 1.5.4 User Acceptance Testing
  └── 1.6 Deployment
      ├── 1.6.1 Server Setup
      ├── 1.6.2 Deployment
      └── 1.6.3 Training

Software Project Management Plan (SPMP)

The SPMP is a formal document that describes how the project will be executed, monitored, and controlled. IEEE Standard 1058 defines the structure:

  1. Introduction: Project overview, deliverables, schedule summary, budget summary
  2. Project Organization: Process model, organizational structure, roles and responsibilities
  3. Managerial Process: Management objectives, assumptions, constraints, risk management, monitoring and controlling mechanisms, staffing plan
  4. Technical Process: Methods, tools, and techniques; documentation plan; project support functions
  5. Work Packages, Schedule, and Budget: WBS, task dependencies, schedule, resource allocation, budget

8.5 Software Project Scheduling and Techniques

Project Scheduling

Project scheduling transforms the action plan (WBS) into a time-ordered sequence of activities. It establishes when each activity should start and end, identifies dependencies between activities, and allocates resources.

Scheduling Techniques

1. Gantt Charts

A Gantt chart is a horizontal bar chart that shows the schedule of project activities along a timeline. Each bar represents a task, its start date, duration, and end date. 

  Gantt Chart Example:

  Task                    Week 1  Week 2  Week 3  Week 4  Week 5  Week 6
  Requirements Gathering  ██████
  System Design                   ██████████████
  Database Design                         ██████
  Frontend Development                            ██████████████
  Backend Development                     ██████████████████████
  Testing                                                 ██████████████
  Deployment                                                      ██████

2. PERT Chart (Network Diagram)

PERT (Program Evaluation and Review Technique) uses a network diagram to show task dependencies and critical paths.

3. Critical Path Method (CPM)

The Critical Path Method identifies the longest sequence of dependent tasks (the critical path) which determines the minimum project duration. Any delay in a critical path task delays the entire project.

Note: PERT and CPM are covered in detail in Unit 9.

8.6 Software Project Team Management and Organization

Team Structures

1. Democratic Decentralized (DD)

  • No permanent leader; decisions made by consensus
  • Communication is horizontal
  • Best for research-oriented, exploratory projects
  • Good for complex problems requiring creative solutions

2. Controlled Decentralized (CD)

  • Has a recognized leader who coordinates tasks
  • Sub-groups may have their own leaders
  • Horizontal communication within sub-groups; vertical between leader and sub-groups
  • Best for medium to large projects

3. Controlled Centralized (CC)

  • Top-level leader makes all decisions
  • Communication flows vertically through the leader
  • Good for well-understood problems with tight deadlines
  • Efficient but can be a bottleneck

Team Organization Models

Model Structure Best For
Chief Programmer Team Chief programmer directs all work; supported by backup programmer and librarian Small, well-defined projects
Egoless (Democratic) All members are equal; rotate leadership Research, innovative projects
Matrix Organization Team members report to both functional manager and project manager Large organizations with multiple projects
Agile/Scrum Team Self-organizing, cross-functional team (5-9 members) Iterative, rapidly changing projects

Communication Challenges

As team size increases, communication complexity grows dramatically: 

  Communication Paths = n(n-1) / 2

  Where n = number of team members

  Examples:
    3 members  →  3 paths
    5 members  →  10 paths
    10 members →  45 paths
    20 members →  190 paths
    50 members →  1,225 paths
Brooks's Law: "Adding manpower to a late software project makes it later." New team members require time to learn the system and increase communication overhead. This is why maintaining small, focused teams is crucial.

8.7 Project Estimation Techniques: COCOMO Model

What is Software Estimation?

Software estimation is the process of predicting the effort, cost, and time required to develop software. Accurate estimation is crucial for project planning, budgeting, and resource allocation.

Estimation Techniques Overview

  • Expert Judgment: Based on experience of experts (Delphi technique)
  • Analogy-Based: Comparing with similar completed projects
  • Algorithmic Models: Mathematical formulas (COCOMO, Function Points)
  • Bottom-Up: Estimate each task individually and sum up
  • Top-Down: Estimate overall project and decompose

COCOMO Model (COnstructive COst MOdel)

The COCOMO model, developed by Barry Boehm in 1981, is an algorithmic software cost estimation model. It uses a mathematical formula based on the estimated size of the software (in KLOC — Kilo Lines of Code).

Three Levels of COCOMO

1. Basic COCOMO

Provides a rough order-of-magnitude estimate. Uses only project size (KLOC) as the input parameter. 

  Effort (person-months) = a × (KLOC)^b
  Development Time (months) = c × (Effort)^d
  People Required = Effort / Development Time
Project Type a b c d Description
Organic 2.4 1.05 2.5 0.38 Small teams, familiar environment, well-understood problems
Semi-Detached 3.0 1.12 2.5 0.35 Medium teams, mix of experienced and inexperienced, moderately complex
Embedded 3.6 1.20 2.5 0.32 Tight constraints, complex interfaces, novel algorithms, high reliability

Worked Example: Basic COCOMO

  Given: An organic project estimated at 32 KLOC

  Effort = 2.4 × (32)^1.05
         = 2.4 × 36.96
         = 88.7 person-months

  Development Time = 2.5 × (88.7)^0.38
                   = 2.5 × 5.97
                   = 14.9 months ≈ 15 months

  People Required = 88.7 / 14.9
                  = 5.95 ≈ 6 people


  Given: An embedded project estimated at 128 KLOC

  Effort = 3.6 × (128)^1.20
         = 3.6 × 412.5
         = 1485.1 person-months

  Development Time = 2.5 × (1485.1)^0.32
                   = 2.5 × 9.71
                   = 24.3 months ≈ 24 months

  People Required = 1485.1 / 24.3
                  = 61.1 ≈ 61 people

2. Intermediate COCOMO

Extends Basic COCOMO by incorporating 15 cost drivers that adjust the effort estimate based on product attributes, hardware attributes, personnel attributes, and project attributes.

Cost Drivers

Category Cost Driver Description
Product RELY (Required reliability) Consequence of software failure (very low to very high)
Product DATA (Database size) Size of database relative to program size
Product CPLX (Product complexity) Complexity of the software module
Hardware TIME (Execution time constraint) Percentage of available execution time used
Hardware STOR (Main storage constraint) Percentage of available memory used
Hardware VIRT (Virtual machine volatility) Frequency of changes to underlying platform
Hardware TURN (Computer turnaround time) Response time of the development computer
Personnel ACAP (Analyst capability) Experience and ability of analysts
Personnel AEXP (Application experience) Team experience with the application domain
Personnel PCAP (Programmer capability) Experience and ability of programmers
Personnel VEXP (Virtual machine experience) Team experience with the platform/language
Personnel LEXP (Language experience) Team experience with the programming language
Project MODP (Modern programming practices) Use of modern SE practices
Project TOOL (Use of software tools) Level of tool support
Project SCED (Required development schedule) Schedule compression/expansion 
  Intermediate COCOMO Formula:

  Effort = a × (KLOC)^b × EAF

  Where EAF (Effort Adjustment Factor) = product of all 15 cost driver ratings

  Example:
    If EAF = 0.92 (experienced team, low complexity):
    Effort = 2.4 × (32)^1.05 × 0.92
           = 88.7 × 0.92
           = 81.6 person-months (reduced from 88.7)

3. Detailed COCOMO

The most detailed level, which provides a phase-by-phase estimate of effort. Each phase (requirements, design, coding, testing) has its own set of cost driver multipliers. This provides more granular estimates for resource allocation and scheduling at the phase level.

COCOMO II

COCOMO II (1997) is the updated version designed for modern software development:

  • Supports estimation at different stages of the project lifecycle
  • Three sub-models: Application Composition, Early Design, Post-Architecture
  • Uses 17 cost drivers (updated from the original 15)
  • Considers reuse, COTS integration, and process maturity
  • Uses function points as an alternative size measure
Summary: Software project management encompasses people, product, process, and project management. The project manager plays a critical role in planning, executing, and controlling the project. Estimation techniques like COCOMO provide mathematical models for predicting effort and cost. Understanding team dynamics, communication complexity (n(n-1)/2), and Brooks's Law is essential for effective project management.
